# Design：Frontend Visual Language Evolution

## 1. Design Intent

本 change 不以“更炫”为目标，而以“更能承托第一人称现场”为目标。视觉应让用户愿意停下来留下一句话、一张图片或一段声音，同时不制造记录焦虑、未来压力或 AI 依赖。

```text
相同核心路径
  留下此刻 → 保存 → 结束
        │
        ├─ 可选：邀请见证者
        └─ 可选：交给时间 / 放入篇章

四套候选视觉语言
  → 相同内容与交互骨架
  → 比较产品气质、表达清晰度、可读性、微信可行性、辨识度
  → 产品负责人只锁定一套主方向
```

## 2. Current Baseline

- 技术目标：Uniapp + Vue 3 + Pinia + WeChat Mini Program。
- 当前主视觉：暖纸、墨色、朱砂、宋体、纸纹与信笺卡片。
- 当前事实：`tokens.css` 已有视觉变量，但 `App.vue`、通用组件和各页面仍存在冷灰底色、重复导航、硬编码色值与不同卡片语言。
- M1 事实：首页、时光轴、个人中心及多项二级页面已按 `Docs/design/home-v2/` 重建；视觉对照、长内容导航遮挡、token/共享组件收口等仍有未完成项。
- 产品边界：安静、纸张、私人档案；首页主叙事是“给此刻一个位置”；保存默认无声音；支持减少动态；不做 major frontend visual reconstruction。

## 3. Candidate Directions

### A. 纸上留白 / Quiet Paper Editorial

- 从当前宣纸朱砂演进，而非复刻古风信纸。
- 使用温暖低对比底色、现代中文衬线、少量朱砂和大面积负空间。
- 动效：墨迹式文字揭示、保存后细线落印、轻微纸面抬升。
- 优势：产品契合度最高、迁移风险最低。
- 风险：若继续堆叠印章、折角和纸纹，会显得主题化和装饰过度。

### B. 私人馆藏 / Contemporary Personal Archive

- 参考现代博物馆与编辑索引：黑白/骨白基底、强类型层级、日期编号、窄色彩强调。
- 记录像“馆藏条目”而不是卡片 feed；时间篇章像展签/章节页。
- 动效：索引行展开、图像遮罩揭示、日期列推进、内容层级平滑重排。
- 优势：现代、清晰、长期档案感强。
- 风险：过度冷峻时会削弱私人温度，并可能把个人中心变成管理后台。

### C. 生命剪贴 / Living Scrapbook

- 以用户照片、声音波形、时间票据和不规则但受控的图文拼贴为视觉主体。
- 无媒体时仍以排版成立，不自动补素材或生成假照片。
- 动效：照片轻微错层、卡片堆叠、相邻片段交叉淡化、声音/图片附件柔和展开。
- 优势：第一人称现场感最强，适合承载真实媒体。
- 风险：信息密度、可读性和低端设备性能更难控制；不能变成社交图片流。

### D. 暮色回声 / Dusk Temporal Cinema

- 深墨、暖灰、低亮度照片和时间光点，突出“此刻与过去相遇”的情绪。
- 首页仍保持快速记录；深色叙事主要用于时间回看和抵达片段，不默认覆盖所有写作页面。
- 动效：由暗到明的内容显现、远近层次淡化、日期/时间点缓慢聚焦。
- 优势：时间回看辨识度强、沉浸感好。
- 风险：深色长文阅读、情绪过重和“电影预告片感”；必须避免把普通记录渲染成宏大人生叙事。

## 4. Common Prototype Slice

四个方向都必须制作同一切片：

1. 首页：品牌、主问题、留下此刻主动作、最近片段/抵达信息、三个一级 Tab。
2. 记录编辑器：文字主输入、图片/声音/位置次级入口、保存反馈、见证者次级入口。
3. 时光轴：月/日层级、普通片段、媒体片段、时间篇章分隔、空/加载/失败状态。

固定合成内容不得包含真实用户信息。原型数据应覆盖：一句短文字、一张合成图片占位、一段合成声音状态、一条 SEALED、一条 UNLOCKED、一个时间篇章。

## 5. Motion System

### 5.1 Motion levels

| Level | 用途 | 建议时长 | 约束 |
| --- | --- | --- | --- |
| L0 | 静态/减少动态 | 0–120ms | 所有语义完整可见 |
| L1 | 按压、选中、展开微交互 | 120–240ms | 只用 opacity/transform/color 为主 |
| L2 | 保存仪式、时间节点、图片揭示 | 320–700ms | 仅由用户明确动作触发，不循环 |
| L3 | 液体、3D、重视差、滚动劫持 | 原型观察项 | 不进入第一版生产实现 |

### 5.2 Recommended motifs

- 保存此刻：正文保持不动，页面内细线/朱砂点或时间编号完成一次轻量确认；不自动跳封存、分享或对话。
- 时间轴推进：可见区域内的时间线从上一节点延伸到当前节点；静态降级为完整线与节点。
- 文字揭示：使用逐块 clip/opacity，而不是逐字打字机；不得拖慢阅读。
- 卡片堆叠：只用于媒体或篇章预览；列表浏览保持自然滚动，不劫持滚动位置。
- 图像转场：缩放幅度克制，使用遮罩/淡化；不依赖 blur/filter 才能理解内容。
- 页面过渡：优先页面内 sheet、section 与共享元素的轻量过渡；不假设 Web 端跨页动画在微信小程序中等价可用。

### 5.3 Motion safety

- 不默认播放声音；触感属于后续可选验证，不在本 Gate 1 实现。
- 不通过闪烁、持续脉冲或高频位移吸引用户回访。
- 不把保存成功、失败、SEALED/UNLOCKED 或 Preview 状态只放在动画中。
- 支持减少动态：去除位移、堆叠和时间线绘制，保留即时 opacity/color 状态反馈。
- 动画失败、掉帧或被禁用时，页面结构与业务动作必须完整可用。

## 6. External Design Boundary

- Open Design 默认模式为 Open Design Cloud；正式生成会使用用户的 Open Design Cloud account/credits，必须在工具可用且 brief 确认后单独启动。
- 外部 brief 仅包含产品定位、布局约束、合成内容和公开参考链接。
- 不发送真实日记、prompt、Agent 回复、用户画像、账号、媒体、位置、token、password、secret 或本机绝对路径。
- 每套方向是独立逻辑生成；不得在一次生成失败后静默切换到 Local Codex 或 secure BYOK。

## 7. Selection Rubric

| 维度 | 权重 | 核心问题 |
| --- | ---: | --- |
| 产品气质 | 30% | 是否像私人生命片段空间，而非展示站/管理台？ |
| 表达清晰 | 25% | 是否让“留下此刻”成为无歧义主动作？ |
| 阅读与无障碍 | 20% | 长文字、媒体、深浅色与减少动态是否可读？ |
| 微信可行性 | 15% | 是否可用小程序稳定能力实现并安全降级？ |
| 辨识度 | 10% | 去掉 logo 后是否仍有 Flashback 自己的视觉性格？ |

任何方向若破坏三个一级 Tab、canonical naming、Preview 隔离、第一人称内容权或保存主路径，直接淘汰，不由加权得分补偿。

## 8. Staged Implementation Shape

仅在 Gate 2 获批后：

1. 锁定设计 token 与 motion token，不新增生产主题切换器。
2. 实现首页、编辑器、时光轴样板切片并做开发者工具视觉核对。
3. 稳定后抽取页面壳层、底部导航、按钮、卡片、时间节点与状态组件。
4. 分批迁移我的记录、详情、时间篇章、个人中心和登录页。
5. 每批保持业务契约与 Preview fail-closed，完成 type-check/build/视觉/安全区/减少动态验证。

## 9. Decision Records

### D1：新建后继 change，不扩写 M1

- 选择：`frontend-visual-language-evolution` 作为唯一 active change。
- 原因：M1 锁死单一 HTML 高保真转译且禁止替代风格；本次目标是比较多风格。
- 代价：必须显式保留 M1 未完成验收，不可假装历史债务消失。

### D2：先比较四套候选，不直接确定“宣纸朱砂 2.0”

- 选择：同内容、同屏幕、同功能骨架比较四套方向。
- 原因：用户明确希望尝试更多风格；只有可比原型才能避免凭形容词选方向。
- 代价：Gate 1 时间增加，但能减少后续全站返工。

### D3：候选是替代方案，不是生产主题

- 选择：最终只锁定一个主方向。
- 原因：多主题会扩大 token、组件、QA 和可访问性矩阵，且没有用户价值证据。
- 代价：未选方向只保留为探索证据。

### D4：动效按 L0–L3 分级

- 选择：第一版只实施 L1/L2；L3 仅作为原型观察项。
- 原因：吸收特别动效不等于复制重型 Web 技术。
- 代价：部分 Awwwards 效果只能保留意图，不能像素级复刻。

### D5：外部原型只使用合成内容

- 选择：Open Design 不接收任何真实用户内容或本机项目隐私材料。
- 原因：日记、prompt、回复、媒体和位置属于高敏数据。
- 代价：真实内容密度与情绪适配仍需在本地/受控环境验证。

### D6：先样板页，后共享组件，最后分批迁移

- 选择：首页、编辑器、时光轴先稳定，再抽取 token/组件。
- 原因：避免 token-first 强迫旧骨架，也避免一次性大重构。
- 代价：短期内新旧页面会暂时共存，需明确迁移边界。
