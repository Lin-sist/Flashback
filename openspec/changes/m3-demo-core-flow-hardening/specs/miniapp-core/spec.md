# Mini Program Core Spec Delta

## ADDED Requirements

### Requirement: M3 Demo Core Flow Must Be Complete

M3 SHALL harden the user-side demo loop so it can be completed through real or explicitly demo-safe behavior.

#### Scenario: User completes the M3 demo loop

- GIVEN the user can authenticate through account/password or WeChat login
- WHEN the user creates a record, lets AI organize "你当时以为", seals it, reaches unlock, enters 时间回看, fills "后来其实", and manually generates a stage summary
- THEN the flow SHALL remain coherent and user-scoped
- AND no admin, production launch, or notification-center feature SHALL be required to complete the demo

### Requirement: Account Password Login Must Remain Available

M3 SHALL preserve the existing account/password login path.

#### Scenario: User chooses account password login

- WHEN the user logs in with a supported account/password credential
- THEN the system SHALL allow the login if validation passes
- AND M3 work SHALL NOT remove this path in favor of WeChat-only login

### Requirement: WeChat Login Must Be Supported

M3 SHALL support real WeChat Mini Program code login when configuration is available.

#### Scenario: User logs in through WeChat

- GIVEN the Mini Program receives a login code from WeChat
- WHEN the frontend sends the code to the backend
- THEN the backend SHALL exchange the code for trusted WeChat identity data
- AND the user SHALL receive the normal authenticated session response if validation passes

#### Scenario: WeChat login configuration is missing

- GIVEN required WeChat login configuration is missing
- WHEN the user attempts WeChat login
- THEN the system SHALL fail explicitly with demo-safe behavior
- AND it SHALL NOT silently create fake production identity success

### Requirement: Record Editor Must Support M3 Reflection Inputs

M3 record creation and editing SHALL support the fields required for the reflection loop.

#### Scenario: AI organizes what the user thought then

- GIVEN the user has written original record content
- WHEN the user actively triggers AI organization
- THEN the system MAY populate "你当时以为"
- AND the original user content SHALL remain preserved

#### Scenario: Life node record is created

- GIVEN the user creates a NODE_RECORD
- WHEN the user selects a supported life node enum
- THEN the record SHALL store or return enough information to display the selected life node

#### Scenario: Other life node label is provided

- GIVEN the user selects "其他" as the life node enum
- WHEN the user provides a custom life node label
- THEN the custom label SHALL be accepted if validation passes

### Requirement: Time Review Must Support Later Reflection

M3 时间回看 SHALL support "后来其实" only after unlock.

#### Scenario: User opens an unlocked record

- GIVEN a record is UNLOCKED
- AND the authenticated user owns the record
- AND the later-reflection 2-submit limit has not been exhausted
- WHEN the user opens 时间回看
- THEN the page SHALL display the original content and "你当时以为" when available
- AND the user SHALL be able to create or update "后来其实"

#### Scenario: Later reflection edit limit is exhausted

- GIVEN the user has submitted "后来其实" 2 times for an unlocked record
- WHEN the user opens 时间回看
- THEN the page SHALL NOT show the "修改" action for "后来其实"

#### Scenario: User attempts later reflection before unlock

- GIVEN a record is not UNLOCKED
- WHEN the user attempts to create or update "后来其实"
- THEN the system SHALL reject or hide the action
- AND the record content SHALL remain unchanged

### Requirement: Unlock Reminder Authorization Must Not Undo Seal

M3 seal flow MAY request WeChat subscription authorization after a record is sealed.

#### Scenario: User refuses subscription authorization

- GIVEN the record seal operation has succeeded
- WHEN the user refuses or cannot complete subscription authorization
- THEN the record SHALL remain sealed
- AND the system SHALL preserve a safe reminder status or fallback state

### Requirement: Stage Summary Must Be User Manual

M3 stage summary SHALL be generated by explicit user action.

#### Scenario: User requests stage summary

- WHEN the user manually triggers stage summary generation
- THEN the system SHALL generate a user-scoped summary from eligible user-owned data
- AND the summary SHALL remain a reflection support feature rather than a forced lifecycle step
- AND M3 SHALL NOT require persisted summary history

### Requirement: M3 Visible Naming Must Stay V2.0 Consistent

M3 user-visible copy SHALL continue to use the V2.0 canonical names.

#### Scenario: Agent updates M3 UI copy

- WHEN navigation, page titles, buttons, or empty states mention records, timeline, or review
- THEN visible naming SHALL use "我的记录", "时光轴", and "时间回看" where applicable
- AND older labels such as "时间轴" or "回看页" SHOULD NOT be introduced unless explicitly justified
