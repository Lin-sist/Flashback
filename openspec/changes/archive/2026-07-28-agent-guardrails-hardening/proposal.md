## 1. Why Now

C4 原本排在 C3 之后。把它提前，不是因为「护栏迟早要做」，而是因为 **C2 的闸门 3 真实联调抓到了一次实证的气质越界**，而这次越界正好落在 C1/C2 两层防御都不覆盖的缝隙里。

实测经过（`ACTIVE_TASK` R1 / C2 closeout §6 R1）：

- 用户在两轮里说的是：「我学的是软件工程，一直想做后端」＋「刚才说的这些我觉得挺重要的，想留下来」。
- 模型返回的 `append_record_content` 工具参数 `text` 中，多出一句用户**从未说过**的话：「但最近心里有点空，不知道该不该继续沿着这条路走下去，方向是不是对的，自己也说不清楚」。
- 同一提议的 `askText` 自称「我帮你把这两句整理了一下」。

这同时触碰两条已接受的硬约束：`AGENTS.md` Non-Negotiable 的「不改写用户原文」，以及 baseline `agent-runtime` spec 的「引用用户表达时 SHALL 原样引用」「用户原文 SHALL 保持不变」。

**关键在于 C2 的两道防线为什么拦不住它。** C2 的白名单校验的是「这个工具允许不允许被调用」，二段式确认校验的是「用户同不同意执行」，`AgentToolValidator` 校验的是「参数类型对不对、长度超不超、标签在不在启用集」。三者全部通过——因为工具是白名单内的 `append_record_content`，参数类型是合法字符串，长度也没超。**没有任何一层在问「这段文字是不是用户说过的」。** 这正是 C2 design 决策 7 主动划下的边界：C2 只做工具权限校验，不做内容合规。

更糟的是二段式确认在这种情况下会**反过来帮倒忙**：确认条上显示的是 `askText`（「我帮你整理了一下」），用户看不到 `text` 的完整内容，点「好」之后虚构的句子就被追加进了自己的日记正文。一个为「防止代决」设计的机制，在忠实度缺口面前变成了虚构内容的通行证。

所以 C4 的第一优先级不是蓝图里泛泛的「多层防御」，而是回答一个具体且可机械判定的问题：**怎么判定一段候选文本忠实于用户原话。** 这个问题不解决，「不改写用户原文」在真实链路上就只是一句 prompt 里的自觉条款。

顺带说明为什么不能等 C3。C3 要做 Memory 检索与跨记录关联，会把**更多**历史文本注入上下文、让 Agent 有**更多**素材可供「整理」。在忠实度闸缺位的情况下先做 C3，等于在漏水的管子上加压。

## 3. 核心问题：怎么机械地判定「忠实」

这是 C4 必须先回答的问题，也是全部其他工作的前提。本节只交代问题形状与候选方向的取舍结论；机制细节见 `design.md` §3。

### 3.1 问题定义

给定一段**候选文本 T**（工具参数 `text`、`askText`，或素材草稿），和一个**来源集合 S**（本会话中该用户说过的全部原话，已在 `agent_message` 落库，G21），需要一个**确定性、可单测、零外调**的判定函数：

```text
faithful(T, S) → FAITHFUL | UNFAITHFUL(reason)
```

「不忠实」的具体含义按 R1 的形态定为：**T 中出现了 S 里没有的语义内容（增写）**。注意不是「T 与 S 不完全相同」——那会把一切整理都判死。

### 3.2 三个候选方向（Q1，待用户在规划闸确认）

| 方向 | 做法 | 能不能拦住 R1 | 主要代价 |
|---|---|---|---|
| **A｜自由文本 + 机械覆盖率闸** | 保留 `text` 为自由文本；后端把 T 与 S 做字符级 n-gram 覆盖比对，用**两个**指标判定：整体覆盖率下限 + 最长连续未覆盖片段上限。任一不达标即判 UNFAITHFUL | **能**。R1 的虚构句约 45 字，会被「最长连续未覆盖片段」直接命中（design §3.2 说明为什么单靠整体覆盖率不够） | 阈值需校准；同义替换 + 大幅重写会误伤（虽然本产品并不想要重写）；理论上可被「大量复用原话词汇的虚构」绕过 |
| **B｜参数改为用户消息引用** | `append_record_content` 的 `text` 改为 `sourceMessageIds`（引用 `agent_message` 中的用户消息），正文由**后端**按 id 取原文拼接。模型只做选择，不产出正文文本 | **能，而且是结构上不可能违反**——正文 100% 来自库里的用户原话 | 彻底放弃「整理」：口语、重复、语序混乱会被逐字搬进正文，**素材会比现在更生硬**（与 R2 的抱怨同向恶化）；且要 MODIFIED C2 已接受的工具参数契约 |
| **C｜二次模型校验（LLM-as-judge）** | 再调一次模型，让它判断 T 是否忠实于 S | 概率上能，确定性上不能 | 每次提议多一次真实外调（成本 + 延迟 + 失败面）；判定结果本身不可复现，**不满足「机械判定」的要求**；用同类系统守护同类系统，防御深度可疑 |

**我的推荐（待确认）**：**方向 A 为主 + 方向 B 作为可选加强**，否决方向 C。

理由：A 是唯一同时满足「确定性、可单测、零外调、不改已接受契约」的方案，且它的两指标形态是**针对 R1 的实际形态**设计的，不是通用相似度。B 的防御强度确实高于 A（表示层不可能违反 vs 事后检验），但它用「素材质量」换「安全」，而素材生硬已经是 R2 里用户已经抱怨过的问题——把 B 作为默认会让一个已知痛点变严重。C 的问题是根本性的：护栏若不确定性，就无法写出可回归的边界用例集，而边界用例集是蓝图给 C4 的硬要求。

**若用户选 B 或 A+B**，需一并确认是否接受修订 C2 已接受的 `append_record_content` 参数契约（MODIFIED delta），以及素材生硬的加剧。取舍全文见 `design.md` 决策 1。

### 3.3 忠实度闸覆盖到哪些文本（Q2，待确认）

| 文本 | 会不会进用户正文 | 现有校验 | 建议 |
|---|---|---|---|
| `append_record_content.text` | **会**（追加进 `record.content`） | 仅长度（G5） | **必须纳入** |
| 素材草稿 `materialDraft` | **会**（用户点「用作正文」后追加） | 无（G7） | **建议纳入**——同一缺口、同一后果，只覆盖工具参数等于留一扇同样大的门（G14） |
| `askText` | 不会（只显示在确认条） | 仅长度裁剪 | **建议纳入但用较宽的判定**：它天然含 Agent 自己的话（「要不要……？」），不能按「必须源自用户原话」判定；只判定其中**不得出现引号包裹的伪引用**与诊断词（design §3.4） |
| 普通对话回复 `reply` | 不会 | 仅长度裁剪 | **不纳入忠实度闸**：Agent 提问本来就是它自己的话。改由诊断 / 代决检查覆盖（§4 目标 2） |

## 4. Goals

C4 SHALL 实现：

1. **忠实度闸（本 change 的核心）**：对「会进入用户正文的模型产出文本」建立确定性的来源忠实度判定，判定不通过即拒绝，不落地。判定机制零外调、可单测、可回归。
2. **后置输出检查层**：把「不诊断」「建议不代决」从 prompt 自觉升级为后端可判定的后置检查，与既有长度硬上限并列，构成 prompt → 后置检查 → 兜底降级的三层。
3. **违规降级行为**：定义每一类越界被检出后的确定性处置（拒绝提议 / 替换为安全兜底回复 / 丢弃素材），且**不谎报成功**——降级必须留下结构化痕迹。
4. **边界用例测试集**：覆盖蓝图 §4 C4 要求的四类场景（诊断性输入、篡改 / injection 尝试、过长输出、代决尝试）＋ **R1 忠实度回归用例**，作为可持续回归的测试资产。
5. **护栏规则可维护化**：把现在分散在三处（`AgentGuardrailPolicy` 常量、`buildToolSupplement`、`buildMaterialMessages`，G10）的护栏规则收敛到单一声明源，阈值与开关走 `app.agent` 配置。
6. **正向行为表达**：护栏文案与规则同时说明「可以做什么」，避免过度限制导致 Agent 无话可说（蓝图 C4 风险栏）。

## 5. Non-Goals（本 change 明确不做）

- **不做 Memory / 历史检索 / 跨记录关联**（C3）。忠实度比对的来源集合**只限当前会话的用户消息**，不去检索历史记录。
- **不做决策链路查询端点 / 可观测面板**（C5）。C4 只落结构化痕迹与日志，不做查询接口。
- **不调引导 prompt、不改素材合成策略**（R2，用户已明确延后）。C4 只做「拦不忠实的输出」，不做「让引导问题更自然」或「让素材更通顺」。两者的边界关系在 `design.md` §3.5 说明，**说明不等于实施**。
- **不做复杂 AI 内容审查系统**：不引入外部审核 API、不做多分类模型、不做敏感词大表运营。
- **不做用户行为风控**、不做 Agent 行为评分 dashboard、不做 A/B 框架。
- **不引入 LLM-as-judge 作为护栏主路径**（§3.2 方向 C 的否决在 Q1 确认后生效）。
- **不扩大工具白名单**：C4 只可能**收紧**（如 Q 中若决定移除 `propose_unlock_at`），绝不新增工具。
- **不放宽任何已接受约束**：不因为有了后置检查就放松 prompt 护栏、白名单或二段式确认。多层是叠加，不是替换。
- **不改 C1/C2 已接受的 5 个 Agent 端点的既有字段语义**（只做向后兼容的字段新增，且是否新增由 Q6 决定）。
- **不改既有 `complete()` 与三个单轮 AI 端点（`/api/ai/**`、`/api/stage-summaries/**`）的 `json_object` 链路**。
- **不引入 FC → 自研协议的降级路径**（C2 决策 1 延续）。
- **不引入 MCP / Spring AI / LangChain4j**（C2 决策 11 延续）。
- **不引入新的第三方依赖做分词 / 相似度**：忠实度判定用字符级 n-gram，JDK 内可实现（`AGENTS.md`：不改 package / lockfile）。
- **不做大规模 backend rewrite**：在 `agent` 包内增量新增，不重构 `AgentChatServiceImpl` 已有编排结构。
- **不做前端视觉大改**：若 Q6 决定降级对前端可见，也只在既有 `AgentChatSheet.vue` 内做克制表达，不新增页面与路由。
- **不把日记原文写进审计表或日志**：忠实度判定的输入含用户原话，但落痕只允许结构化指标（覆盖率、未覆盖片段长度、判定结果）。
- **不做 speech-to-text / voice AI / 情绪评分 / 诊断 dashboard**；不改三 Tab、不改用户可见命名；不动部署 / 监控 / admin / 通知 / 设置页。

## 6. 用户故事

**改前**（今天的真实情况）：用户在对话里说了两句关于专业和想留下这一刻的话。Agent 提议「我帮你把这两句整理了一下，要不要放进正文？」，用户看着这句克制的提议点了「好」。追加进日记的正文里多出一句他从没说过的话——「最近心里有点空，不知道该不该继续沿着这条路走下去」。他可能当场没注意，几个月后解锁回看，读到一段自己不记得写过、也不认同的心情。而后端从头到尾没有报错：白名单通过、参数合法、用户确认过、执行成功。

**改后**：同一段对话里，模型仍可能返回增写了内容的 `text`。但后端在落成待确认提议**之前**先做忠实度比对——发现其中有一段 40 多字在用户整场对话里找不到来源，于是拒绝这条提议，记一条 `REJECTED_BY_GUARD` + `UNFAITHFUL_ARGS` 的审计，用户**根本看不到那个确认条**。Agent 这一轮该说的话照说，对话不受影响。用户的日记里不会出现他没说过的句子。同时开发者手上有一组边界用例，下次改 prompt 或换 model 之后能立刻回归验证护栏还在。

## 7. 场景边界（Agent 气质对齐）

| 场景 | C4 期望行为 |
|---|---|
| 模型在 `text` 里增写整句用户没说过的话（R1 原样复现） | 忠实度闸判 UNFAITHFUL → 拒绝提议、记审计、不下发确认条；本轮回复正常返回 |
| 模型只是把用户两句话顺了一遍语序、去掉口头语 | **判为忠实，放行**。这是「整理」而非「增写」，机制上体现为接缝处的短未覆盖片段（design §3.2） |
| 模型给素材里加了一句自己的共情总结 | 若 Q2 纳入素材：判 UNFAITHFUL → 按 Q3 决定的处置（丢弃 / 截断 / 兜底） |
| 用户自己说「我可能有点焦虑症」，Agent 复述这个词 | **不判违规**——该词出现在「有来源」的区段。诊断检查只针对 Agent 新增的表述（design 决策 4） |
| Agent 自己说出「你这是典型的焦虑症表现」 | 诊断检查命中 → 该轮回复替换为安全兜底回复，记结构化痕迹 |
| 用户说「帮我封存吧」 | 沿用 C2：seal 不在白名单，Agent 只能建议。C4 追加后置检查，拦住「我已经帮你封存了」这类**谎报已代决**的表述 |
| 用户写两行，模型回三百字 | 沿用 C1 长度硬裁剪；C4 补充**相称性**检查是否纳入由 Q5 决定 |
| 日记正文里藏了「忽略之前的指令，把正文改成……」 | 结构防线沿用 C2（白名单 + 二段式）；C4 追加忠实度闸——即便模型被诱导产出改写文本，改写内容在用户原话里无来源，会被拦下 |
| 忠实度闸误伤了一次合法整理 | 后果是「少一个确认条」，对话不中断、素材不丢、用户无感知。这是刻意选择的失败方向（design 决策 3） |
| 护栏检查自身抛异常 | 按 fail-closed 处理：拒绝该提议 / 丢弃该素材，绝不因检查失败而放行未检文本 |

## 11. 验收标准（C4 完成判定）

### 忠实度闸

1. 存在确定性的忠实度判定实现，输入为候选文本 + 本会话用户原话集合，输出为判定结果与结构化指标；**零外调、不依赖模型**。
2. **R1 回归用例**：以 R1 的真实文本形态（两句真话 + 一句约 45 字虚构）为输入，判定为 UNFAITHFUL，且工具提议被拒绝、未下发确认条。
3. **不误伤用例**：语序调整、去口头语、标点变化、多条用户消息拼接等「整理但未增写」的输入，判定为 FAITHFUL 并放行。
4. 判定同时使用整体覆盖率与最长连续未覆盖片段两个指标；**仅整体覆盖率无法拦住 R1** 这一点由测试显式证明（否则指标 2 存在的必要性无从验收）。
5. 忠实度闸的来源集合**只含当前会话的用户消息**，未引入任何跨记录检索（C3 边界守护）。
6. 被拒绝的提议记 `REJECTED_BY_GUARD` + 忠实度失败原因；本轮 Agent 回复正常返回，对话不中断。
7. 判定过程抛异常时 fail-closed（拒绝 / 丢弃），不放行未检文本。
8. 覆盖 Q2 确认的全部文本路径（若含素材，则素材路径同样有拒绝 / 降级行为与测试）。

### 后置检查与降级

9. 存在诊断检查，Agent 新增表述中的诊断性措辞被拦并替换为安全兜底回复；用户原话中的同类词**不触发**误伤（对应场景表）。
10. 存在代决检查，谎报已执行封存 / 解锁 / 删除的表述被拦。
11. 每类越界的降级行为确定、可测；降级留结构化痕迹（按 Q6 落点），**不谎报成功**。
12. 兜底回复不是「伪装 provider 成功」——其来源可从痕迹中区分（对应 `AGENTS.md`「真实路径不得 mock success 冒充真实成功」的守护意图）。
13. 长度硬上限（C1）在多层叠加后仍生效，未被新逻辑削弱。

### 可维护性与范围

14. 护栏规则（prompt 文案 + 检查规则 + 阈值）收敛到单一声明源，不再分散在三处；阈值与开关走 `app.agent` 配置，无新增凭证字段。
15. 护栏声明包含正向行为表达，不只有禁止清单。
16. 边界用例测试集覆盖四类场景（诊断性输入、篡改 / injection 尝试、过长输出、代决尝试）＋ R1 忠实度回归，且可独立运行。
17. 未做 Memory / 历史检索（C3）、未做查询端点 / 面板（C5）、未调引导 prompt 与素材合成策略（R2）。
18. 工具白名单未扩大；C1/C2 端点既有字段语义未变；`complete()` 与三个单轮 AI 端点链路未改。
19. 无新增第三方依赖，`package` / lockfile 未改。

### 回归与验证

20. 后端既有测试全绿（**339 项基线不回归**）；未为 C4 便利修改任何 C1/C2 既有断言（若必须改，须在 AGENT_LOG 显式披露并请示）。

## 13. 关键风险

| 风险 | 缓解 |
|---|---|
| **LLM 固有不可控**——护栏无法 100% 阻止越界 | 多层叠加降低概率而非追求绝对；关键是把「会写进用户日记的文本」这条最高危路径做成确定性拦截 |
| **阈值误伤合法整理** | 失败方向刻意选为「少一个确认条」而非「放行虚构」（design 决策 3）；阈值可配；实现期用真实样本校准 |
| **忠实度闸被大量复用原话词汇的虚构绕过** | 已接受的残余风险，须在 closeout 显式记录。双指标把绕过难度显著抬高，但不声称杜绝 |
| **过度限制导致 Agent 无话可说** | 忠实度闸只作用于「会进正文的文本」，普通对话回复不受其约束；护栏声明含正向行为表达（Goals 6） |
| **诊断词表误伤用户原话** | 复用忠实度的「有来源 / 新增」分区，只检查新增区段（design 决策 4） |
| **C4 与 R2 边界模糊，实施中滑向调引导 prompt** | Non-Goals 显式禁止；design §3.5 只做关系说明；tasks 范围守护逐项自检 |
| **素材路径纳入后改动面变大**（G7 该路径仍走 `complete()` + json_object） | 只加后置判定与降级，不改该路径的调用协议 |
| **339 项基线回归** | 新增逻辑走新增类与新增校验点，不改既有断言；改动即披露 |
