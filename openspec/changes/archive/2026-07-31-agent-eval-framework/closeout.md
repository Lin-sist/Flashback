## 4. 实现期的五处发现

1. **回归基线实测是 536 / 4，不是规划期沿用的 534 / 3**（E37）。AGENT_LOG 里早已记录
   536 / 4（三个 Type B 之后），是 `ACTIVE_TASK` 顶部与蓝图 §2 摘要没跟上。
   已修 `ACTIVE_TASK`；**蓝图不动**（已冻结）。这是第二次触发「规划期判断实现期必须复核」
   （第一次是 E28 的行数）。

2. **护栏的一处真实边界**（非缺陷修复）：「用户自己说过的病名可以复述」的成立条件比直觉窄——
   取决于 Agent 是否连带复用了周边 4-gram。同一用户输入下
   「你说有点焦虑症…」放行、「你说的焦虑症…」判 `diagnostic`。属 n-gram 方案固有性质与
   C4 刻意选的误伤方向（代价是用户收到兜底回复，而非错误内容外发）。
   **未校准任何阈值**，改为把边界写成一条用例钉住现状。

3. **修掉一条自己写的假用例**：截断用例最初样本 111 字（< 120 上限），
   于是「不超过 120」恒成立而**什么都没验**。改成远超上限的文本 +
   新增「长度恰好等于上限」断言。**这类「恒成立所以什么都没测」的断言值得单独警惕**。

4. **snakeyaml 把未加引号的 timestamp 自动转成 `java.util.Date`**，
   `LocalDateTime.parse` 会拿到 `"Sun Mar 15 05:00:00 SGT 2026"` 而失败。
   两头都处理了：解析层兼容 `Date`，用例里也加引号——只做后者等于留一条
   「靠人记得加引号」的规矩。

5. **`ArgumentCaptor` 不适合多轮取轨迹**：captor 拿到的是同一个可变对象的引用，
   多轮时读到的全是最后一轮终态。改用按 persist 顺序记录的手写替身。

## 5. 关键设计取舍（细节见 design.md 12 条决策）

- **断言轨迹信号而非回复措辞**：后者把评测绑死在模型语言输出上，换 model 就全红且看不出问题在哪一步。
- **替身只替两处边界**（mapper 与 provider HTTP），护栏 / 状态机 / 上下文组装 / 记忆截断 /
  工具校验全走生产实现。替身替掉的越多，被覆盖的生产代码越少。
- **provider 替身继承生产类只覆写两个真正发请求的方法**，因此「配置是否可用」
  「model 是否在 FC 白名单内」仍由生产逻辑判定。整体 mock 会把它们一并 stub 掉。
- **替身走非 mock 分支**：生产代码在 `isMockProvider()` 处直接返回、压根不组装 prompt，
  所以只走内置 mock 响应器的评测会同时缺上下文组装维度且产不出任何降级轨迹（E7）。
- **不提供自动刷新开关**：有了它，「评测红了」的最短路径就从「停下来想想」
  变成「跑个命令让它变绿」。手工编辑的摩擦在这里是特性。
- **checksum 双向测试**：「只改说明 checksum 也必须变」容易被漏，但少了它机制是残缺的。
