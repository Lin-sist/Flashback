## 2. 项目定位

项目名称：时光回序 Flashback V2.0。

产品形态：微信小程序“人生节点/情绪记录与延迟回看系统”。

核心产品闭环：

写下此刻
→ 保存草稿或封存记录
→ 到期自动解锁
→ 在时光轴中重新看到过去的记录
→ 查看“那时的我”
→ 填写“现在的我”
→ 可选回信

产品强调私密、克制、温和、具有时间感，不是效率仪表盘、社交平台或心理诊断工具。

三个一级 Tab 固定为：

- 首页
- 时光轴
- 个人中心

用户可见核心命名：

- 我的记录
- 时光轴
- 时间回看

## 4. 当前架构

整体结构：

微信小程序
→ API Service / Pinia
→ Spring MVC Controller
→ Service
→ MyBatis Mapper
→ MySQL

辅助基础设施：

- Redis：登录 Token 黑名单等状态
- JWT：用户认证
- 微信接口：登录与订阅消息
- AI Provider：DeepSeek / OpenAI-compatible
- ObjectStorageProvider：Qiniu / S3-compatible
- 定时解锁任务：扫描到期封存记录并执行幂等解锁

后端不是 Spring Security 项目，目前更准确的说法是：

- JWT + Spring MVC 拦截器鉴权
- BCrypt 密码哈希
- Redis Token 黑名单
- 用户资源归属校验

简历中不应写成“基于 Spring Security 完成鉴权”，除非暑期确实完成迁移。

## 5. 已确认实现的核心能力

### 5.1 用户与认证

已实现：

- 账号密码注册与登录
- 微信 `code2session` 登录
- JWT 签发与校验
- Redis Token 黑名单
- BCrypt 密码哈希
- 用户资料查询和修改
- Controller 鉴权测试

### 5.2 记录状态机

核心状态：

- `DRAFT`
- `SEALED`
- `UNLOCKED`

已实现：

- 新建草稿
- 更新草稿
- 删除草稿
- 封存记录
- 定时解锁
- 记录列表和详情
- 已解锁记录查询
- 回信
- 标签
- 后来感受/时间回看相关字段

封存之后，位置、附件和封面不可继续修改。

### 5.3 AI 能力

已实现：

- AI 写作提示
- 单条记录结构化总结
- 阶段总结
- DeepSeek / OpenAI-compatible 调用
- Provider 配置抽象
- 强制结构化 JSON 输出
- 超时控制
- 明确的 AI 状态：
  - `SUCCESS`
  - `UNAVAILABLE`
  - `FAILED`
  - `FALLBACK`
- AI 失败不阻塞记录保存和封存
- 真实用户路径不把 mock 输出伪装成真实 AI 成功
- AI 原则上只辅助整理，不覆盖用户原始内容

需要特别注意：

- 当前实现可以称为“多 Provider 配置/三种 Provider 状态选择”。
- 但底层真实模型调用主要复用一个 OpenAI-compatible Adapter。
- 不要把它包装成复杂的 AI Agent、多模型编排、RAG 或模型路由平台。

### 5.4 位置能力

已实现：

- 当前定位
- 地图选择
- 手动输入
- 草稿状态修改和删除
- 封存后只读
- 解锁后的时间回看展示
- 权限拒绝不会阻塞记录编辑

后端不负责地理编码或逆地理编码，只保存小程序提交的坐标、名称和地址。

### 5.5 图片、语音、对象存储与封面

已实现：

- 图片选择和默认压缩
- 原始语音录制与上传
- 图片预览
- 语音播放
- 草稿图片删除
- 草稿语音删除和重录
- 从同一记录的图片附件中选择封面
- 私有 Bucket
- 后端签发上传授权
- 上传后由后端验证对象存在
- 后端生成短期签名访问 URL
- Qiniu Provider
- S3-compatible Provider
- 已持久化附件按自身 Provider 路由
- 封存后禁止修改附件和封面

约束：

- 每条记录最多 9 张图片
- 每条记录最多 9 个语音文件
- 单文件最大 40 MB
- 单条记录附件总量最大 300 MB
- 语音只保存原始音频，不做转写或语音 AI 分析

### 5.6 时光轴

已实现：

- 按创建时间展示记录
- 单标签筛选
- 年/月/日筛选
- 标签和日期条件使用 AND 语义
- 分页加载
- 稳定排序：`created_at DESC, id DESC`
- 返回 `TimelinePageVO`
- 按年月分组
- 前端增量加载时合并重复月份并按记录 ID 去重
- Preview 与真实模式保持基本一致

### 5.7 Preview 隔离

项目保留显式 Preview 模式，用于无登录演示。

真实登录用户路径必须使用后端数据，不能：

- 把 Preview 数据混入真实用户记录
- 把 mock AI 当作真实成功
- 用静态首页数据冒充后端数据

## 10. 逆向学习方法

请 Web GPT 不要只给我答案，而要作为项目导师：

1. 每次只选择一个小模块。
2. 先让我画图、预测调用链或解释代码。
3. 再根据真实文件纠正。
4. 让我自己定位 Controller、Service、Mapper、SQL 和测试。
5. 通过追问确认我是否真的理解。
6. 给我一个小型修改任务。
7. 要求我先写测试或验收条件。
8. 修改完成后让我解释：
   - 为什么这样改
   - 有哪些替代方案
   - 哪些边界没有覆盖
   - 面试官可能怎么追问
9. 把学习结果记录成：
   - 已掌握
   - 能在提示下完成
   - 只能看懂
   - 尚未掌握
10. 定期进行无提示复述和模拟面试。

建议每个模块使用以下闭环：

项目地图
→ 文件定位
→ 调用链复述
→ 核心代码阅读
→ 自己画图
→ 面试追问
→ 小改动
→ 测试
→ 复盘
→ 间隔复习
