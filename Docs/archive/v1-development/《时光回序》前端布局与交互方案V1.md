# 《时光回序》前端布局与交互方案 v1

## 1. 文档目的

本文档用于统一《时光回序》微信小程序前端的页面职责、布局逻辑、导航结构、核心交互和动效方向，方便后续使用 Copilot、Codex 进行代码生成、重构、审查与联调。

本文档优先服务于以下目标：

1. 固定当前 MVP 的前端信息架构与页面分工
2. 避免首页、档案页、时间轴页之间职责重叠
3. 固定首页到详情页、新建页之间的核心交互逻辑
4. 为 Uniapp + Vue 3 + Pinia 的实际工程实现提供明确约束

---

## 2. 当前产品核心定位

《时光回序》是一个**私密的时间记录产品**。

它不是：

* 社交社区
* 效率工具
* 信息流产品
* AI 聊天产品

它应该是一个：

* 安静的
* 克制的
* 私密的
* 温柔的
* 有时间感和仪式感的
* 像“私人时间档案馆”一样的产品

核心主流程固定为：

`进入档案馆首页 -> 点击 + 写下此刻 -> 保存草稿 / 封存 -> 等待抵达 -> 解锁回看 -> 可选回信`

---

## 3. 顶层信息架构

### 3.1 一级结构

底层一级结构固定为 3 个主区域：

1. **首页（档案馆）**
2. **时间轴**
3. **个人中心**

### 3.2 全局主动作

* 全局主动作不是底部 tab，而是首页右下角的悬浮 `+` 按钮
* `+` 的含义固定为：**写下此刻 / 新建记录**
* 新建页不占用底部导航主位

### 3.3 页面职责分工

#### 首页（档案馆）

负责：

* 承接用户首次进入后的主要浏览
* 展示用户最关心的信件内容
* 提供草稿 / 已封存 / 已拆封信件的快速入口
* 承接进入新建页的主动作

#### 时间轴

负责：

* 按时间回望自己的记录
* 提供纵向叙事感，而非管理感

#### 个人中心

负责：

* 用户资料
* 隐私与安全
* 数据同步
* 关于产品

#### 档案管理页（由首页进入，不作为一级 tab）

负责：

* 查看全部记录
* 状态筛选
* 搜索与排序
* 管理与批量浏览

说明：

* 原“我的记录”页面后续统一命名为：**档案管理页** 或 **我的档案**
* 该页面不再承担首页式的大展陈职责，避免与首页冲突

## 4. 首页布局与交互方案

## 4.1 首页定位

首页不是写信页，而是**私人时间档案馆入口**。

首页需要兼顾：

* 美观性
* 情绪感
* 快速浏览
* 快速进入具体信件
* 快速发起新建记录

## 4.2 首页布局结构

首页从上到下分为四层：

### 第一层：顶部导航

* 左：菜单 / 抽屉入口
* 中：产品名“时光回序”
* 右：最近解锁提醒 / 历史入口 / 状态入口

### 第二层：情绪标题区

* 一句主标题，例如“那些被封存的碎片”
* 一句很轻的辅助说明
* 只用于定调，不承载复杂功能

### 第三层：三段式信件区

按照状态分为 3 个模块，自上而下排列：

1. 草稿
2. 已封存
3. 已拆封

每个模块结构：

* 左上角：状态标题
* 右上角：查看全部
* 中间：横向滑动的信件卡片组

说明：

* 每个状态模块中的卡片支持左右滑动
* 更多信件像卡牌一样流动切换
* 首页当前已确定使用卡片样式承载三类信件

### 第四层：全局悬浮 +

* 固定在首页右下角
* 始终作为“写下此刻”的主入口
* 视觉上显著，但不能破坏整体克制感

## 4.3 首页交互逻辑

### 卡片点击进入逻辑

* 点击草稿卡片：进入编辑页
* 点击已封存卡片：进入封存详情页
* 点击已拆封卡片：进入解锁阅读页

### 查看全部逻辑

* 点击某个状态模块的“查看全部”
* 进入档案管理页
* 自动带入对应状态筛选

## 4.4 首页保留交互备忘（后续可实现）

以下交互已作为布局与后续代码实现备忘保留：

1. **首页信件卡片点击后，卡片由中心向屏幕四周平滑扩展**

   * 像把用户“吸入”信件内部
   * 用于首页到详情页 / 编辑页的主要过渡动效

2. **草稿 / 已封存 / 已拆封模块支持左右滑动**

   * 更多信件像卡牌流动切换
   * 优先保证平滑与克制，不追求复杂 3D 特效

说明：

* 以上交互先作为布局依据保留
* MVP 阶段可做低保真版本
* 后续可根据小程序性能与开发成本决定是否升级

## 5. 新建 / 编辑页布局与交互方案

## 5.1 页面定位

新建 / 编辑页是“落笔封存页”。

它的核心不是填写表单，而是：

* 写下此刻
* 保留仪式感
* 让用户像在一张展开的纸上认真写给未来的自己

## 5.2 页面布局

新建页保留当前已确定样式：

* 不做传统导航栏
* 页面主体像一张展开的纸
* 大面积留白
* 中心书写容器
* 附加信息低存在感

页面结构：

### 顶部区域

* 不显示常规导航栏
* 右上角保留一个浅浅的 `x`
* `x` 用于关闭当前页面并返回首页

### 主书写区

* 标题 / 时间信息
* 正文输入区
* 留白充足
* 避免表单感和分栏感

### 附加信息区

* 地点
* 图片
* 语音
* 这些入口只做轻量补充，不能抢正文视觉中心

### 主按钮

* 底部主按钮为：**封存这一刻**
* 草稿保存不做并列强按钮
* 页面关闭或离开时自动保存草稿

## 5.3 新建页核心动效（已确认）

### 进入动效

* 用户点击首页右下角 `+`
* 新建页像一张纸，从 `+` 号所在位置开始出现
* 动效方向：**从右下角向左上角展开**
* 像纸张被抽出、展开，并逐渐填满整个屏幕
* 当页面展开完成后，首页的 `+` 号消失

### 退出动效

* 用户点击右上角浅色 `x`
* 当前新建页自动保存用户书写内容为草稿
* 随后页面像纸张一样收回
* 收回方向与进入相反：**向右下角收回进首页的 `+` 号**
* 收回后回到首页
* 首页的 `+` 号重新出现

### 动效实现原则

* 动效应克制、柔和、平滑
* 不要夸张弹跳
* 不要复杂多段特效
* 保持“纸张展开 / 收回”的隐喻

## 5.4 草稿进入编辑页逻辑

* 当用户从首页点击某个草稿卡片时
* 进入的仍然是同一个新建 / 编辑页
* 只是页面数据为已有草稿
* 页面结构和样式不变

## 6. 已封存详情页布局与交互方案

## 6.1 页面定位

已封存详情页的核心是：**等待抵达**。

它不是阅读页，也不是可编辑页。

它应该告诉用户：

* 这封信已经被封存
* 现在不能打开
* 它会在未来某个时间点抵达

## 6.2 布局结构

### 顶部

* 返回按钮
* 标题 / 日期 / 解锁时间

### 主体

* 一张沉睡中的信件卡
* 可显示片段摘要或虚化后的内容
* 重点是“等待感”，而不是阅读感

### 底部信息

* 解锁时间
* 距开启还有多久
* 一句轻提示，例如“现在只需等待它抵达”

## 6.3 交互逻辑

* 从首页已封存卡片点击进入
* 使用首页卡片“吸入式扩展”过渡
* 页面内不提供“手动解封”操作
* 页面交互保持极简

---

## 7. 解锁阅读页布局与交互方案

## 7.1 页面定位

解锁阅读页是全产品的**情绪峰值页**。

用户进入该页面的目的不是管理，而是：

* 重新读到过去的自己
* 感受时间已经流过
* 决定是否给过去的自己补上一句回应

## 7.2 布局结构

页面分为两段：

### 第一段：旧信正文区

* 顶部仅保留极轻的时间 / 地点 / 编号信息
* 主体是一张偏暖色的旧信正文卡
* 正文是视觉中心
* 中文为主叙事，英文只做极轻的辅助标签

### 第二段：附言回应区

* 位于正文之后
* 不是普通输入框
* 更像“信末附言区”
* 像读完旧信后，轻轻补上一句迟到的回答

推荐文案方向：

* 此刻，想对当时的自己说句什么……
* 给过去的自己补上一句回应
* 留下一句现在的回答

按钮方向：

* 留下回应
* 写一句回信
* 给过去的我一句话

## 7.3 交互逻辑

* 从首页已拆封卡片点击进入
* 卡片从首页“吸入式扩展”为整张旧信
* 正文滚动到底后，附言区自然出现或平滑承接
* 回信提交成功后，不跳页
* 回信区原地变为“已写附言卡”

## 7.4 注意事项

* 不做博客详情页
* 不做聊天对话页
* 不做评论框
* 不让英文信息抢戏

## 8. 时间轴页布局与交互方案

## 8.1 页面定位

时间轴页是“人生回望页”。

它不是首页，也不是管理页。

用户来到这里，是为了：

* 按时间查看自己的历史记录
* 以纵向叙事方式回望过去

## 8.2 布局结构

### 顶部

* 页面标题，例如“时间长廊” / “时间轴”
* 一句轻说明，例如“在此处，凝视那些被封存的往昔与尚未开启的明日。”

### 主体

* 一条纵向细时间线贯穿页面
* 节点按时间排序
* 节点状态可分为：

  1. 草稿
  2. 已封存
  3. 已拆封

### 节点表现规则

* 普通节点：仅显示日期 + 标题
* 重要节点：显示小型内容卡
* 不要每个节点都做大卡片
* 保持“轴”的节奏和回望感

## 8.3 交互逻辑

* 纵向滑动浏览
* 点击节点进入对应详情
* 当前时间点可有“此时此刻”标记
* 时间轴页的进入详情动效可比首页更轻

## 8.4 页面语气

* 安静
* 克制
* 像走在一条时间长廊中
* 不做图表分析页
* 不做复杂统计页

## 9. 档案管理页（原“我的记录”）布局与交互方案

## 9.1 页面重新定位

当前“我的记录”页面与首页存在视觉与职责冲突。

因此后续统一将其定位为：

* **档案管理页**
* 或 **我的档案**

该页不再承担首页式的大卡片展陈职责。

## 9.2 页面职责

该页负责：

* 查看全部记录
* 按状态筛选
* 搜索与排序
* 管理与批量浏览

## 9.3 布局结构

### 顶部

* 页面标题：我的档案 / 档案管理
* 一句轻说明

### 筛选区

* 状态筛选：全部 / 草稿 / 已封存 / 已拆封
* 排序：最近更新 / 创建时间 / 解锁时间
* 搜索入口可折叠，不抢视觉中心

### 列表区

后续不再使用首页那种大展陈卡片。

建议使用：

* 中等尺寸统一列表卡
* 缩略图可选
* 显示标题、摘要、时间、状态
* 高度统一
* 更像“档案条目”，不是“首页展品”

## 9.4 交互逻辑

* 从首页某状态模块“查看全部”进入
* 自动带入默认筛选
* 点击列表项进入对应详情页
* 进入详情可使用较轻的推进式过渡
* 不与首页争夺情绪中心

## 10. 个人中心布局与交互方案

## 10.1 页面定位

个人中心是“静态控制页”。

它不是首页式内容页，而是：

* 用户资料
* 隐私与安全
* 数据同步
* 关于产品

## 10.2 布局结构

### 第一段：个人头部

* 头像
* 昵称
* 可选一句极简签名

### 第二段：档案设置

* 档案命名
* 展示逻辑
* 数据同步

### 第三段：隐私与安全

* 生物识别进入
* 隐秘模式
* 加密相关

### 第四段：关于与退出

* 服务协议
* 设计理念
* 关于产品
* 退出登录

## 10.3 交互逻辑

* 列表点击为标准设置推进
* 不追求情绪化大动效
* 保持设计系统一致即可

## 11. 页面间过渡与动效建议

## 11.1 首页 -> 新建页

* `+` 号触发
* 纸张从右下角抽出并展开
* 填满整个屏幕

## 11.2 新建页 -> 首页

* 点击右上角 `x`
* 自动保存草稿
* 页面像纸张一样收回到 `+` 中
* 首页 `+` 重新出现

## 11.3 首页 -> 草稿 / 已封存 / 已拆封详情

* 使用卡片中心扩展、向四周平滑过渡的方式
* 像用户被“吸入”信件中

## 11.4 首页 -> 档案管理页

* 普通推进式过渡即可
* 不使用过强戏剧性动效

## 11.5 时间轴 / 档案管理 -> 详情

* 使用较轻的放大或推进过渡
* 比首页进入详情更弱

## 11.6 通用动效原则

* 克制
* 柔和
* 时间感
* 不弹跳
* 不游戏化
* 不复杂 3D
* 优先保证真实小程序性能

## 12. 工程实现建议（面向 Copilot / Codex）

## 12.1 技术前提

固定技术路线：

* 微信小程序
* Uniapp
* Vue 3 Composition API
* Pinia

## 12.2 页面建议路由

仅为建议命名，可按工程实际调整：

* `/pages/home/index`
* `/pages/editor/index`
* `/pages/record-detail/index`
* `/pages/sealed-detail/index`
* `/pages/timeline/index`
* `/pages/archive/index`
* `/pages/profile/index`

## 12.3 建议组件

建议抽象以下核心组件：

* `ArchiveStatusSection`
* `ArchiveCard`
* `DraftCard`
* `SealedCard`
* `UnlockedCard`
* `FloatingCreateButton`
* `PaperEditorContainer`
* `SealActionButton`
* `ReplyAppendCard`
* `TimelineNode`
* `ArchiveListItem`
* `ProfileSettingItem`

## 12.4 状态建议

建议前端显式处理以下业务状态：

* `DRAFT`
* `SEALED`
* `UNLOCKED`

页面路由参数建议显式区分：

* 页面来源（首页 / 时间轴 / 档案页）
* 当前记录状态
* 是否已存在回信

## 12.5 草稿自动保存建议

新建 / 编辑页需支持：

* 输入内容变更后延迟自动保存
* 点击 `x` 时强制保存一次
* 返回首页时恢复首页列表状态

## 14. 当前确认结论

当前前端布局逻辑确认如下：

1. 首页作为私人时间档案馆入口
2. 新建页通过首页右下角 `+` 进入
3. 新建页使用“纸张从 + 中展开 / 收回”的动效方案
4. 首页三类信件分区展示，并支持横向滑动
5. 首页卡片点击后进入详情使用“吸入式扩展”过渡
6. 档案管理页不再与首页争夺展陈角色
7. 时间轴页作为回望叙事页
8. 解锁页作为情绪峰值页
9. 个人中心作为静态控制页
