## 0. 给人与 Agent 的阅读、权限与执行约定

### 0.1 本文回答什么

本文回答：

- C1–C9 能力底座完成后，Flashback 下一阶段为什么转向核心体验与信任兑现；
- 哪些产品语义已冻结，哪些必须先做原型或真实验证；
- 主线 change 的顺序、依赖、非目标与停止条件；
- 每一刀需要什么层级的证据，才能诚实地进入下一刀。

本文不回答具体 API、DTO、数据库字段、枚举命名、后台任务实现、Provider 调用预算或最终动效参数。这些内容必须在对应 OpenSpec change 的 proposal / design / tasks / delta 中决策。

### 0.2 事实源优先级

| 层 | 事实源 | 作用 |
|---|---|---|
| 硬规则 | `AGENTS.md` | Non-Negotiable、Type、Gates、证据和提交责任 |
| 当前行为 | `openspec/specs/**` | 已接受的用户可见行为与工程契约 |
| 长期方向 | `core-product-definition.md` | 产品为什么存在、以后做与不做什么 |
| 方向序列 | 本文 | 先做什么、何时停、何时继续 |
| 本轮执行 | `openspec/changes/<change-id>/` | 一刀的范围、设计、任务与 delta |
| 会话交接 | `.ai/ACTIVE_TASK.md` / `.ai/AGENT_LOG.md` | 当前状态、进展与验证证据 |

若长期方向与 accepted specs 有差异，现有实现继续服从 accepted specs；只能通过新的 Type C change 改变 baseline。本文不直接改写任何现有契约。

### 0.3 权限与三道闸门

- 本文冻结只批准方向，不批准业务实现。
- 任一 Type C 必须新建独立 OpenSpec change，并且一次最多一个 active change。
- 规划批准、实现授权、真实外调/副作用授权三道闸门继续分离。
- 真实批量 AI、真实对象存储联调、push、部署、发布必须分别获得授权。
- 提交责任默认“用户手动提交”；未明确授权时 Agent 不得 stage / commit / push。

### 0.4 证据分层

以下证据不得互相冒充：

- 单元测试 / H2：验证确定性逻辑与不变量；
- build / scripted probe：验证构建、契约形状与固定分支；
- 真实 MySQL：验证 DDL、迁移、锁、外键与事务语义；
- 真实对象存储：验证授权、提交、私有读取与远端删除；
- 真实 provider：验证实际模型链路的小样本行为；
- 微信开发者工具 / 真机：验证录音、播放、权限、导航与真实交互；
- 原型 / 用户访谈：验证心智模型、语言与体验假设。

无法执行的验证必须写 `SKIPPED + 原因`，不能用较低层证据替代。

`iteration-blueprint-v1.2.md` 记录 C1–C9 的 Agent 能力叙事、旧 Optional C0/C10/C11 与工程 ADR。它已经完成历史使命，不再是当前执行序列，但仍是能力来源和技术叙事证据。

## 1. v2.0 的总方向

### 1.1 一句话

> **让 C1–C9 的 Agent 能力退到产品背后，先让用户不依赖 Agent、不依赖封存，也能完整地留下一个属于自己的此刻。**

### 1.2 驱动目标的变化

| 蓝图代际 | 主驱动 | 已完成 / 要完成 |
|---|---|---|
| v1.2 | Agent 能力叙事 | Loop、Tool、Memory、Guardrail、Trace、Eval、Reflection、Resilience、Temporal Intelligence |
| v2.0 | 核心体验与信任兑现 | 独立记录、数据主权、见证者对齐、记忆主动权、验证后时间组织 |

下一阶段不继续按技术名词堆能力。任何主线工作必须能解释它如何改善：

```text
一个想留下但未必说清楚的此刻
  → 用户留下文字 / 图片 / 原始声音
  → 保存本身完成价值
  → 用户可以结束，也可以主动邀请见证者或交给时间
  → 记录始终可查看、带走和删除
```

### 1.3 北极星时刻

> 用户带着一个想留下但未必说清楚的此刻进入，最终保存了一段自己认可、仍然属于自己的第一人称生命片段。

北极星不使用日记原文做分析，也不以记录总数、每日活跃、连续签到、聊天时长或未来打开率衡量产品价值。

### 1.4 成功层级

1. **当下成立**：不用 Agent、不封存，也能完成真实记录。
2. **长期托付**：用户能查看、导出、删除，不被数据和订阅锁定。
3. **主动理解**：用户主动邀请时，Agent 才作为见证者帮助表达。
4. **时间复利**：权限允许且证据充分时，过去被温柔交还。
5. **组织生活**：只有原型证明自然时，时间篇章才进入实现。

## 2. 当前能力与产品差距

### 2.1 已确认的底座

- M4 已提供真实 authenticated record path、私有对象存储、位置、图片、原始声音、封面、时光轴与 Preview 隔离。
- Phase 1 / Phase 2 的 C1–C9 均已归档。
- 三个一级 Tab、被动 Agent 入口、用户确认素材、封存不可变、时间归属护栏、失败分类和真实小样本验证均已有基础。

### 2.2 已确认的主要差距

| 能力 | 当前状态 | v2.0 方向 |
|---|---|---|
| 首页 | 仍以未来信件、封存和抵达为视觉中心 | 第一入口改为“留下此刻” |
| 保存语义 | 用户保存后仍叫 DRAFT | 保存后成为正式 SAVED / RECORDED |
| 最小片段 | 正文必填；图片/声音不能独立成立 | 文字、图片、声音任一种均可成立 |
| 记录分类 | 必须选择旧三类之一 | 普通此刻片段成为默认，不强制分类 |
| 自动保存 | 关闭页面会把内容永久保存为可见草稿 | 未确认内容只进入短期技术恢复草稿 |
| 删除 | 仅 DRAFT 可删 | 所有状态可删 |
| 导出 | 真实能力不存在 | 离线可读、可迁移的完整导出 |
| 设置表面 | authenticated path 存在假备份、假访问控制等本地状态 | 真实路径只展示真实能力 |
| Agent 角色 | Prompt 仍声称“一个朋友” | 有朋友温度的见证者 |
| Agent 对话 | 固定情绪→困惑→核心问题→期待阶段 | 用户意图驱动、可随时停、不强制追问 |
| 历史记忆 | 有 cue 时可自动检索，用户无可见授权 | 默认关闭、按次授权、有出处、可撤销 |
| 时间篇章 | 尚无验证 | 先原型与访谈，正证据后再实现 |

### 2.3 一个必须先拆开的耦合

当前 `DRAFT` 同时承担三种职责：

```text
用户认为“已经保存的记录”
        +
媒体上传 / Agent 会话所需的技术容器
        +
所有可编辑业务对象
```

如果只改按钮文案，媒体上传、Agent 状态校验、删除和迁移仍会互相冲突。因此 P3.1 必须是端到端 Type C，不拆成只有 UI 或只有后端状态的一半实现。

| D58 | 时间篇章先验证；若实施，片段默认零个篇章、第一版最多一个主篇章、用户主动创建/命名/归入，结束可撤销 |

| D60 | 公开 Agent 前必须完成最低安全闸；品牌渐进调整；指标只采结构化行为，不采私人内容；旧 Optional 保持证据触发 |

## 5. 意图卡片

### 5.1 H0 · `truth-surface-cleanup`

**现状**：真实登录路径存在仅由本地状态驱动的数据备份、iCloud 同步、访问控制等页面，能够造成能力已经启用的误解。

**目标**：authenticated real path 只展示真实存在的能力。

**建议改法**：

- 隐藏或停用没有真实后端契约的入口；
- 若 Preview 保留，显式标注“概念预览，不代表已启用”；
- 不在 H0 假实现导出、备份、锁屏或同步。

**非目标**：真实备份、账号注销、跨端同步、设置页大改。

**验收**：路由与可见入口静态审查；authenticated / Preview 分支检查；小程序构建；有环境时微信手验。

### 5.2 E0 · `capture-ritual-prototype`

**要验证的问题**：

- 用户是否确认内容已保存；
- 是否理解可以立即离开；
- 是否误以为必须封存或使用 Agent；
- 编辑器的分类、人生节点、AI、解锁时间是否造成负担。

**推荐原型基线**：页面内短暂、安静的“这一刻已经留下”；无默认声音；不自动跳封存、分享或继续对话。

**证据**：低成本交互原型、合成材料和目标用户观察；不记录参与者私人日记原文。

### 5.3 P3.1 · `present-moment-capture`

**现状坏事**：用户主动保存后仍看到“草稿”；图片和声音必须先写正文；首页把“寄给未来”放在保存之前。

**用户故事**：

> 改前，用户想只留一张图或一段声音，却被要求先写正文、选择分类并面对封存。
> 改后，他可以留下任一种片段，保存后这一刻已经成立；Agent 和封存都只是可选。

**范围**：

- 技术 DRAFT 与用户 SAVED 分离；
- 迁移现有有效 DRAFT；
- 文字/图片/声音至少一种的保存校验；
- 普通此刻片段默认类型；
- SAVED 编辑、列表、首页、时光轴与状态文案；
- 关闭页面时的恢复草稿，不静默永久保存；
- “交给时间”移到保存后的次级路径；
- authenticated real path 与 Preview 隔离。

**非目标**：时间篇章、数据导出、全量删除、Agent Prompt、跨记录记忆、品牌重建、STT。

**关键风险**：状态扩展会触及 enum、SQL、Mapper、DTO/VO、媒体、位置、封面、Agent 状态校验、前端类型、筛选和测试，不能拆成假 vertical slice。

### 5.4 P3.2 · `data-ownership-foundation`

**现状坏事**：个人中心显示“导出/清除全部”等假入口；真实记录仅 DRAFT 可删；对象存储删除与数据库级联没有全量语义。

**用户故事**：

> 改前，用户被告知可以备份和导出，但点击后没有真实结果，封存内容也无法删除。
> 改后，他可以获得离线可读的完整副本，也可以删除任意记录或清除全部记录。

**导出基线**：

```text
flashback-export/
├─ index.html
├─ records/*.md
├─ media/
├─ manifest.json
└─ README.txt
```

**范围**：

- 原文、明确填写字段、附件与必要元数据；
- Agent 内容单独标注，不混入原文；
- sealed 内容提供“尊重封存 / 完整取回”选择；
- 任意状态单条删除与清除全部记录；
- 关联位置、附件、回信、Agent 会话与派生数据的清理；
- 远端对象幂等清理与失败恢复；
- “数据与所有权”真实页面。

**非目标**：生产备份、iCloud、跨端同步、PDF-only、账号注销。账号生命周期须另建 Type C，并在公开发布前补齐。

### 5.5 P4.1 · `witness-agent-alignment`

**现状坏事**：Prompt 仍称“一个朋友”；固定阶段会把用户带过情绪、困惑、核心问题与期待，即使用户只想留一句话。

**用户故事**：

> 改前，用户主动邀请 AI 后容易进入一段有预设终点的访谈。
> 改后，他可以选择“先听我说”或“帮我理一理”，Agent 不抢表达，也不要求抵达结论。

**范围**：

- 角色与入口文案对齐见证者；
- 用户意图驱动、每轮最多一个问题；
- 极短回答不触发重复盘问；
- 任意阶段可结束；
- DRAFT / SAVED 写作帮助；
- 素材确认、工具确认、原文忠实度与失败不阻塞保存继续保持；
- C6 快照变化须带 `baselineNote` 明确归因。

**非目标**：关系养成、主动关心、长期人格、建议竞争、扩大工具权限、跨记录记忆授权、图框架重写。

### 5.6 P4.2 · `memory-agency`

**现状坏事**：配置开启且有 cue 时，系统可以自动检索并注入过去，用户不知道本轮是否使用、用了什么，也不能撤销。

**用户故事**：

> 改前，Agent 可能突然提到过去，而用户只能猜它为什么知道。
> 改后，默认只看这一刻；用户可按会话允许参考过去，并能查看来源、关闭和纠正。

**范围**：

- 默认跨记录检索与注入为零；
- 会话级“本次可参考过去记录”；
- 回看对话只默认授权目标 UNLOCKED 记录；
- 实际使用来源可查看，但不暴露分数、命中数和内部关键词；
- 记录级“不再供 Agent 参考”；
- “只代表当时，不代表现在”的用户解释；
- 删除和撤销立即影响未来检索；
- AI 推测不自动持久化。

**非目标**：向量库、人格画像、自动阶段总结、情绪趋势、全局永久授权、LLM-as-Judge。

### 5.7 R1 · `safety-response-minimum`

**目标**：公开 Agent 前形成窄、诚实、可验证的安全例外。

**范围原则**：

- 普通低落、失败、迷茫不病理化；
- 证据充分且紧迫的人身风险可打断普通记录；
- 明确自身不是专业救援人员；
- 不声称人工接管或通知已经发生；
- 不形成永久风险标签；
- 地区援助信息在实施时重新核验。

**发布边界**：R1 完成前，Agent 真实用户研究限定为成年人、小规模、知情场景；未成年人另立规划。

### 5.8 E1 / P5.x · 时间篇章

**原型假设**：

- 片段默认属于零个篇章；
- 第一版最多一个主篇章；
- 用户主动创建、命名、加入、结束与重新打开；
- 保存时不要求选择篇章；
- 删除篇章不删除片段；
- 不自动推断“人生阶段”、结果或完成度。

**必须先回答**：用户是否真的用“篇章”理解尚未结束的生活，还是标签和时间范围已经足够。

**停止条件**：若原型显示创建/归入造成分类压力，P5.x 不启动，独立片段继续作为完整产品单位。

## 6. 状态、迁移与编辑边界

### 6.1 产品状态图

```text
技术 DRAFT
  │  可为空；用于上传 / Agent / 恢复；用户记录列表不可见
  │  用户明确保存，且文字 / AVAILABLE 图片 / AVAILABLE 声音至少一种
  ▼
SAVED / RECORDED
  │  已完成产品价值；可继续编辑正文、标题、标签、位置、附件、封面
  │  可再次邀请 Agent；可独立长期存在
  │  用户主动选择未来时间并确认封存
  ▼
SEALED
  │  正文、位置、附件、封面不可修改
  │  所有者仍可删除，也可在导出中明确选择完整取回
  │  时间到达
  ▼
UNLOCKED
     原记录只读；后来表达进入独立区域；所有者仍可删除
```

`SAVED` / `RECORDED` 与 `MOMENT` 均为蓝图语义占位，最终枚举和字段名由 P3.1 design 决定。

### 6.2 保存校验

| 内容 | 是否可独立保存 |
|---|---:|
| 非空文字 | 是 |
| 至少一张已提交图片 | 是 |
| 至少一段已提交原始声音 | 是 |
| 标题 | 否 |
| 地点 | 否 |
| 标签 / 类型 | 否 |
| Agent 尚未确认的回复 | 否 |
| pending / failed 附件 | 否 |

若文字已存在但媒体上传失败，产品可以保存文字并明确展示媒体失败；只有媒体而媒体尚未提交成功时，不能宣称该片段已经保存。

### 6.3 存量迁移

- 规划期先只读统计各状态、正文有效性、附件状态和异常组合；
- 非空正文或 AVAILABLE 附件的现有 DRAFT 提升为 SAVED；
- 空/异常 DRAFT 保持技术状态，不进入用户记录列表；
- 不批量改写旧记录类型、正文、创建时间或封存时间；
- 迁移输出只记录计数与 record id 的安全诊断范围，不记录私人内容；
- 必须用真实 MySQL 验证，H2 不能替代；
- 项目现有增量 SQL 是实施事实，`schema.mysql.sql` 落后问题不与 P3.1 偷偷捆绑。

### 6.4 自动保存

- 用户明确保存之前，不得把恢复行为呈现为永久记录；
- 文本未保存退出时，允许“保存这一刻 / 暂不保存”；
- 因媒体上传或 Agent 会话产生的技术 DRAFT 可短期恢复；
- 恢复入口不使用逾期、连续天数或损失焦虑；
- 自动清理时长和实现方式在 P3.1 proposal 中基于隐私、存储和恢复需求确认。

## 7. 数据所有权与长期托付

### 7.1 导出原则

- 无 Flashback、无 AI、无订阅时仍可读；
- 原始媒体保持原文件；
- 用户原文与 AI 派生内容明确分层；
- manifest 支持未来迁移，但不替代人类可读文件；
- 导出临时文件必须私有、短期、可清理；具体策略由 design 决定；
- 停止付费不阻止导出。

### 7.2 sealed 与所有权

封存是用户主动选择的时间体验，不是平台扣押数据的权利：

- 默认导出可尊重封存，只含必要元数据；
- 用户显式选择完整取回时，清楚提示可能提前看见；
- 完整取回不必改变服务器状态；
- 删除 sealed 记录不要求拆封。

### 7.3 删除原则

- 单条与全部删除都覆盖 DRAFT、SAVED、SEALED、UNLOCKED；
- 用户界面立即不可见；
- 数据库、对象存储和关联派生数据有明确清理语义；
- 远端失败不允许静默遗留可访问私密对象；
- 重试必须幂等，不得复活已删除内容；
- 可以建议先导出，但不能强迫或制造恐惧。

### 7.4 商业底线

- 基础文字记录、查看、导出、删除不锁定；
- 停止付费后旧内容继续可读、可带走、可删除；
- 可收费的是新增媒体存储、Agent 成本、同步、私人时间册等增量服务；
- 达到额度可阻止新增，不得突然锁住或删除旧数据；
- 不用日记内容投放广告或建立外部营销画像；
- 未经明确同意，不将私人记录用于模型训练；
- 第三方模型的数据接收方、目的与保留边界在正式使用前必须可说明。

## 8. 见证者、记忆与时间边界

### 8.1 见证者的体验合同

应当：

- 认真在场，但不抢表达；
- 有温度，但不承诺关系；
- 允许不完整、不知道和停下来；
- 问一个具体问题，而不是完成阶段表；
- 帮助整理用户已经表达的内容；
- 承认可能理解错误。

不应当：

- 声称是朋友、伴侣或最懂用户的人；
- 把一次行为升级为人格；
- 要求用户解释意义、成长或未来；
- 用过去努力要求现在振作；
- 用连续性证明自己有记忆；
- 代替用户封存、删除或修改原始记录。

### 8.2 推荐的会话意图

```text
用户主动邀请
  ├─ 先听我说       → 反映与承接，不强制提问
  └─ 帮我理一理     → 每轮最多一个具体问题

任意分支
  ├─ 用户继续       → 有界回应
  ├─ 用户不知道     → 不重复盘问，可安静承接
  └─ 用户想停止     → 立即收束
```

具体控件与文案先做原型；实现不要求引入新框架，也不要求大规模拆写现有 Agent service。

### 8.3 记忆授权模型

| 场景 | 默认可见范围 |
|---|---|
| 普通写作帮助 | 当前片段 + 当前会话 |
| 用户开启“本次可参考过去记录” | 当前会话内允许检索符合边界的过去记录 |
| 用户打开某条 UNLOCKED 回看对话 | 目标记录自身；其他历史仍需额外授权 |
| 用户关闭授权 | 后续轮次不再跨记录检索与注入 |

### 8.4 来源、纠正与撤销

- 只展示实际使用的来源，不展示检索分数、命中数和关键词；
- 来源可回到对应记录；
- 用户可把某条记录排除出未来 Agent 参考；
- 用户可补充“这只代表当时，不代表现在”；
- 删除记录后立即排除未来检索；
- 撤销阻止未来使用，但不能虚假承诺抹除已经发生的一次模型调用；
- AI 摘要和推测不是自动事实，只有用户确认内容可成为长期候选。

## 9. 时间篇章、环境、安全与品牌

### 9.1 时间篇章

已冻结方向：用户定义、非强制、可撤销、不评价结果。

未冻结实现：创建入口、命名流程、加入方式、结束交互、sealed 片段归属、时间册呈现。必须先做 E1。

### 9.2 环境数据

- 地点、图片和声音只因用户主动选择进入记录；
- 当前位置拒绝不阻塞手动地点或普通记录；
- 手动地点可不含坐标；
- 不后台定位；
- 不自动采集天气、运动、音乐、相册和设备行为；
- 未来环境线索须独立 Type C，包含权限、撤销、端侧与数据最小化决策。

### 9.3 安全与未成年人

- 紧迫人身风险是当下表达优先的窄例外；
- 普通低落不触发病理化提醒；
- 无人工接管时不得声称已通知；
- 不因一次安全响应形成永久标签；
- 地区援助信息实施时须重新核验；
- R1 前的真实 Agent 研究限定成年人、小规模、知情场景；
- 未成年人策略、监护与数据权利另立规划。

### 9.4 视觉、声音与品牌

- 保留安静、纸张、私人档案的气质；
- 减少“未来信件”“严禁翻阅”和重封印仪式对快速记录的压迫；
- 首页主叙事改为“给此刻一个位置”；
- 朱砂印章作为时间能力符号，不主导每次普通保存；
- 保存默认无声音，触感可选；
- 支持减少动态效果；
- 先稳定核心路径，再冻结完整品牌系统；
- 不做 major frontend visual reconstruction。

## 10. 指标、研究与隐私

### 10.1 推荐指标

- 发起“留下此刻”的意图中，最终形成有效 SAVED 片段的比例；
- 首次用户能否不使用 Agent、不封存完成一条记录；
- 文字、图片、声音各真实路径的成功率与失败率；
- 保存后是否理解“已经完成”；
- 导出和删除任务完成率；
- 较长周期后，用户是否仍愿意再次托付一个片段；
- Agent 的人评锚点、边界通过率与来源正确性。

### 10.2 允许的结构化行为

- 开始记录、保存成功/失败；
- 是否包含文字/图片/声音；
- 是否主动邀请 Agent；
- 是否选择封存；
- 导出/删除操作状态。

### 10.3 禁止进入分析与普通日志

- 正文、标题和标签内容；
- 地点名称与坐标；
- 文件名和声音内容；
- Agent 对话原文；
- 推测的情绪、人格、诊断或人生阶段。

### 10.4 原型与访谈

- 使用合成材料或由参与者主动提供、现场不落库的安全材料；
- 报告任务理解、犹豫点、误解与语言反馈；
- 不把 5–8 人的定性验证写成统计显著性；
- 不要求参与者交出真实敏感日记作为研究成本。

## 13. 停止条件与非目标

### 13.1 任何一刀都必须停止的情况

- 用户未批准 proposal / design / tasks / delta；
- 规划批准后仍未获得实现授权；
- 当前已有另一个 active Type C；
- 需要猜测 API、字段、持久化、权限或枚举语义；
- 真实外调或副作用没有单独授权；
- 低层证据与目标验收层级不匹配；
- 原型表明产品假设不成立。

### 13.2 不进入当前主线

- AI 朋友 / 伴侣养成；
- 用户可见 Multi-Agent 团队；
- 自动人格、情绪评分、心理诊断、趋势 dashboard；
- Speech-to-text、声音语义分析；
- Life OS、后台持续感知；
- 社交流、匿名树洞、公开分享主线；
- Notification center、SMS、Admin portal；
- 生产部署、监控、告警和发布；
- LangGraph / Spring AI / MCP 内核化整包重写；
- 大规模 backend rewrite 或 major frontend reconstruction；
- 用历史记录证明用户现在“应该”怎样。
