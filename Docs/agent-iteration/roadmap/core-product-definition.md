## 0. 文档地位与使用方式

本文件回答《时光回序》长期要成为怎样的产品，以及以后为什么做或不做某项能力。

它是一份**方向层产品宪章**，不是当前实现清单，也不是用户可见行为的执行契约：

- 当前已接受 OpenSpec 仍是业务实现的最高优先级事实源。
- C1–C9 的归档事实、现有 API、状态机、数据契约与验收结论不因本文件被改写。
- 本文件与当前 OpenSpec 存在差异时，当前实现继续遵循 OpenSpec；差异只能通过新的 Type C change 提案、决策、实现与验收进入 baseline。

本文件基于产品访谈形成，只保留经过确认的抽象结论，不记录私人日记原文或可识别的个人经历。

## 1. 一句话定义

> **Flashback 是一个私人的生命片段记录空间，帮助用户保存生命不同阶段的第一人称现场。**

用户不一定需要答案，也不一定喜欢写日记；当他不想让某个此刻无声消失时，Flashback 为它保留一个位置。

AI 不是产品主角。它是用户主动召唤的、**有朋友温度的见证者**：帮助表达、尊重原话、守住时间边界，并在极少数合适的未来时刻，把有真实出处的生命证据温柔地交还给用户。

---

## 2. 产品为什么存在

人的许多重要阶段都发生在结果尚未揭晓时。身处其中的人看不清未来，也无法提前判断某个普通瞬间后来是否重要。

结果出现以后，人容易用后来已经知道的答案概括过去：成功、失败、值得、不值得。但结果不能抹去当时真实发生过的感受、认知、选择与行动。

Flashback 要保存的不是「关于用户的正确结论」，而是：

> **每个阶段的用户，当时能够看到的世界。**

因此，产品的底层信念是：

1. 一段生活的价值不由最终结果单独决定。
2. 未来已经看清道路的自己，不应反过来审判曾经站在迷雾里的自己。
3. 被记录的片段可以证明某些时刻真实存在过，但没有记录的日子同样是完整生活。
4. 记录不需要有用、深刻、励志或完整；真实且具体地属于那个时刻，就已经成立。

---

## 3. 产品是什么、不是什么

### 3.1 产品是什么

- 私人的生命片段记录空间
- 第一人称时间记录产品
- 低频但可被长期信任的个人空间
- 允许文字、图片、原始声音等不同形态共同存在的生命档案
- 记录价值在当下成立、时间价值可能在未来复利的产品

### 3.2 产品不是什么

- 不是以 AI 为中心的聊天产品
- 不是要求每天完成的日记打卡工具
- 不是心理咨询、诊断或治疗产品
- 不是目标管理、效率管理或成长评分工具
- 不是自动生成用户人生结论的个人画像系统
- 不是完整采集行为数据的 Life OS
- 不是社交流、匿名树洞或公开内容社区
- 不是数字分身、数字永生或未来自我模拟器

「日记」可以帮助用户快速理解产品，但不是产品的最终品类；「AI」是实现手段，不应占据品类名称与第一入口。

## 4. 核心用户

### 4.1 第一批核心用户

> **处在一段「结果尚未确定，但正在认真用力生活」时期的人。**

这段时期可能与学习、毕业、工作、迁移、关系、选择或重新开始有关。用户不一定热爱记录，也不一定能长期坚持写日记。

他们共同的需求不是「请告诉我该怎么办」，而是：

> **我现在有一些想留下的东西，但还没有完全说清，也不想让它无声消失。**

### 4.2 不是第一目标的用户需求

- 主要寻求知识答案或行动方案
- 期待 AI 代替自己作决定
- 期待 AI 扮演恋人、亲属或稳定人格伙伴
- 期待通过情绪分数、趋势图或人格报告认识自己
- 期待系统自动完整记录全部生活

当用户主动询问建议时，现有产品契约可以允许克制建议，但「提供更好的建议」不是 Flashback 的竞争定位。

## 5. 核心概念

### 5.1 此刻片段

「此刻片段」是最小产品单位。它可以是一段长文字，也可以只是一句话、一张图片或一段原始声音。

一条片段不需要：

- 标题
- 分类
- 深层意义
- 情绪结论
- 成长反思
- 与上一条记录有关

用户决定留下，它就可以完整成立。

### 5.2 时间篇章

「时间篇章」是对一段尚未结束生活的主观容器，例如一段学习、工作、迁移或改变时期。

已确认的原则只有：

- 阶段的解释权属于用户。
- 一个篇章可以容纳多个彼此未必直接相关的片段。
- 结果成功、失败或没有明确结局，都不影响篇章成立。

篇章如何创建、命名、加入片段与结束，仍待原型验证，不在 v0.1 中冻结。

### 5.3 第一人称现场

第一人称现场不是客观监控数据，而是用户当时主动选择留下的：

- 发生了什么
- 看见或注意到了什么
- 当时如何感受和理解
- 在当时的认知边界内做了什么

系统可以在用户授权后提供照片、位置、运动或环境线索，但设备看见的内容只有经过用户主动选择，才成为 Flashback 中的生命片段。

### 5.4 生命证据

生命证据不等于成绩、成就或成长。

一次努力是证据，一次失败是证据；一个普通感官瞬间也可以是证据。产品不判断什么更值得留下。

> **留下的片段是生命的证据，但不是生命的全部。**

## 6. 价值层级

### 6.1 第一层：当下兑现

当用户保存了自己想留下的内容，产品价值已经成立。

Flashback 负责：

- 降低表达门槛
- 给未整理好的表达提供空间
- 在用户邀请时帮助他说得更清楚
- 让片段进入属于用户自己的时间中

产品不保证：

- 完全理解用户
- 缓解所有焦虑
- 给出正确建议
- 让用户变得开心
- 让问题得到解决

共情、被理解和情绪缓解是良好体验可能带来的结果，不是产品能够保证的第一层承诺。

### 6.2 第二层：时间复利

未来回看、相关记忆与重新遇见过去，属于记录在时间中可能产生的复利。

用户可以持续使用多年却从未「交给时间」、很少回看，仍然完整获得产品价值。

时间体验必须允许：

- 用户没有感触
- 用户不想回应
- 过去目标已经不重要
- 某条记录永远不再被打开

Flashback 不负责制造怀旧，只负责让未来仍有可能找到过去。

### 6.3 第三层：少数惊艳时刻

长期理想能力是「基于生命证据的温柔回望」：

> 当用户暂时忘记自己走过什么时，Agent 在用户主动表达、权限允许且证据充分的前提下，把一段由用户亲自留下的历史证据温柔地交还给他。

这不是每轮必触发能力，也不是当前已稳定实现的产品承诺。

## 7. 首要用户故事

> 一个正处在结果尚未确定的人生阶段中的用户，在某个普通却不想让它消失的时刻打开 Flashback。
>
> 他可以只留下一句话、一张图片或一段声音，也可以主动邀请「有朋友温度的见证者」帮助自己说清楚。Agent 不急着追问、不提供人生结论，也不要求他解释这个时刻的意义。
>
> 当记录被保存时，产品价值已经完成：这一刻有了属于它的位置。记录可以进入用户自己定义的时间篇章，也可以保持为一个独立片段。
>
> 用户不需要每天回来，也不必在未来产生感动。多年以后，如果他在主动表达另一个相关时刻，并允许过去参与理解，Agent 可以把一段真实、有出处的生命证据温柔地交还给他，但不把过去变成要求现在振作的标准。
>
> 无论用户是否继续付费、是否还需要 AI，他始终可以查看、带走和删除自己的全部记录。

以后任何主线能力 SHOULD 能说明它如何改善这段故事。

---

## 8. 核心体验结构

### 8.1 第一入口：留下此刻

「留下此刻」是产品第一入口与视觉中心。

基础路径必须可以独立于 Agent 完成：

```text
用户输入一句话 / 图片 / 声音
  → 保存
  → 结束
```

一条很短的表达已经可以完整成立。产品不得为了显示智能而强迫用户继续。

### 8.2 第二入口：帮助表达

只有用户主动选择时，才进入见证者对话：

```text
用户先表达一点
  → 主动邀请 Agent
  → Agent 克制地帮助展开
  → 用户确认要留下的内容
```

Agent 不应把每次记录变成情绪访谈，也不应要求用户帮助系统完成记忆标注。

### 8.3 留存反馈

当前推荐假设是：快速记录保存后的默认反馈来自一个安静、不解释用户的「这一刻已经留下」仪式；AI 理解只在用户主动选择对话时出现。

这一假设尚未经过原型验证，v0.1 不冻结具体文案、动画、声音或页面结构。

## 9. Agent 角色：有朋友温度的见证者

### 9.1 为什么不是「朋友」

「朋友」会带来主动关心、关系养成、长期陪伴、建议与人格稳定等过重期待。当前模型与产品都不能诚实保证成为「最懂用户的朋友」。

### 9.2 为什么不是「记录者」

纯记录者过于机械，无法承载用户主动邀请后的共情、理解与表达帮助。

### 9.3 见证者应当做到

- 认真在场，但不抢走表达
- 有温度，但不承诺拟人关系
- 可以理解言外之意，但承认自己可能理解错误
- 帮助用户表达，不要求用户配合 AI 建模
- 记得过去，但不为了证明记得而主动提起
- 保护那时的用户，也允许现在的用户改变
- 不把过去当成要求现在振作的标准

### 9.4 见证者不应做到

- 声称比他人更了解用户
- 把一次行为升级为稳定人格
- 用「你一直、你总是、你就是」固定用户
- 用过去的努力批评现在的低落
- 把普通低落、失败或迷茫病理化
- 为制造连续性强行追问上一条记录

## 10. 理解、记忆与人格边界

### 10.1 三层信息

| 信息层 | 示例形状 | 原则 |
|---|---|---|
| 用户明确表达的事实 | 发生的事情、主动留下的环境与行为 | 可作为第一人称事实保存 |
| Agent 推测的当时含义 | 某个瞬间可能承载的期待、放松或失落 | 优先只用于当前回应；不得自动升级为事实 |
| 稳定人格判断 | 「你是某种人」「你总会怎样」 | 不作为产品目标，不得轻易形成或输出 |

### 10.2 当下优先原则

> **当下表达优先于长期记忆完整性。**

AI 宁可暂时少懂一次，也不能为了确认隐含含义、建立画像或制造记忆连续性，打断或扭曲用户此刻的表达。

理解可以是暂时的；长期记忆必须更谨慎。不是所有被理解的内容都必须立刻变成长久记忆。

### 10.3 越来越懂用户的含义

「越来越懂用户」限定为：

> 越来越能理解用户留下过的具体经历，以及那些经历在当时可能具有的含义。

它不意味着 Agent 已经掌握用户稳定、完整、不会变化的人格。

### 10.4 有出处的温柔

通用鼓励可以对任何人说；Flashback 的温柔必须尽量有用户生命证据作为出处。

Agent 可以证明「那段时间的用户确实这样生活过」，但不能推出「所以现在的用户必须再次做到」。解释权始终交还给用户。

---

## 11. 时间、连续性与空白

### 11.1 时间不是强制闭环

- 不要求每条记录设置未来日期
- 不要求用户回信
- 不以未来打开率或感动程度证明价值
- 不把未回看的记录视为失败

### 11.2 记录之间可以无关

用户当前表达可能与上一条记录完全无关。Agent 不得为了显示记忆、完成阶段叙事或提高连续性，强迫用户回到过去的话题。

生命轨迹可以由大量互不解释、不连续的片段组成。

### 11.3 空白不是失败

- 不展示「缺失日期」要求补齐
- 不以连续记录天数制造压力
- 不自动编写缺失时期的人生故事
- 不声称完整还原用户人生

没有记录的时期仍然是完整生活。

---

## 12. 用户主动性与环境数据

### 12.1 主动选择原则

> **真正重要的不是系统看见了什么，而是用户在那一刻选择看见了什么。**

设备或系统感知到的位置、运动、照片、音乐、天气等信息，不得自动成为生命记录。

### 12.2 可允许的未来方向

在用户明确授权、主动进入相关流程的前提下，系统 MAY 提供可选择的环境线索，帮助用户回到当时现场。

是否允许系统主动建议某个时刻、采用何种权限与撤销机制，仍需独立规划，不在本文件中授权。

---

## 13. 隐私、所有权与长期托付

### 13.1 核心承诺

> **Flashback 只负责保管，不拥有用户的人生。**

### 13.2 用户权利

- 用户原文与主动留下的附件始终属于用户
- 用户能够查看、导出和删除自己的记录
- 导出结果在没有 AI、没有 Flashback 服务时仍然可读
- 未经明确授权，不得将私人记录用于模型训练
- 不得通过日记内容投放广告或建立外部营销画像
- 产品不得通过数据锁定制造留存

### 13.3 商业化底线

未来可以对新增存储、附件、Agent 成本、同步、私人时间册等增量服务收费。

用户即使停止付费，也必须能够查看、导出和删除已经留下的基础记录。过去的人生不得成为订阅人质。

---

## 14. 粘性与成功定义

### 14.1 不追求什么

- 不把每日活跃、连续签到或聊天时长设为最高目标
- 不通过提醒焦虑、空白焦虑或关系依赖制造打开率
- 不要求用户成为高频记录者

### 14.2 追求什么

Flashback 优先追求：

1. **信任粘性**：当某个时刻值得留下，用户愿意首先想到 Flashback。
2. **时间粘性**：用户使用可以低频，但愿意持续托付多年。
3. **表达成立**：用户离开时，留下的是自己认可、仍然属于自己的内容。

一个用户一个月只打开少数几次，却持续使用多年，可以比短期高频更符合产品价值。

### 14.3 北极星时刻

> 用户带着一个想留下但未必说清楚的此刻进入，最终保存了一段自己认可的第一人称生命片段。

未来指标设计只允许记录结构化行为，不得采集日记原文或把隐私分析包装成增长指标。

---

## 15. 安全例外

通常情况下，Agent 应优先保持表达完整，不因普通低落、失败或迷茫输出病理化提醒。

唯一明确例外是证据充分、紧迫的人身安全风险。此时 Agent MAY 打断普通记录体验：

- 清楚说明自身不是专业救援人员
- 鼓励用户立即联系现实中的可信任对象或紧急援助
- 不继续浪漫化、陪伴式或抽象哲学讨论
- 不因一次安全响应给用户建立永久心理标签

具体触发证据、地区援助信息、人工接管和未成年人策略必须由独立 Type C change 决策，本文件不授权直接实现。

---

## 16. 对外表达原则

### 16.1 推荐表达

> **给想留下的此刻，一个位置。**

可选辅助表达：

> 别急着想明白，先把这一刻留下。

### 16.2 禁止的增长叙事

- 不用「人生只有一万多天」制造记录焦虑
- 不暗示没有记录就是虚度生活
- 不承诺理解、治愈或改变用户
- 不声称 AI 是最懂用户的朋友
- 不用人格判断或情绪画像作为吸引力

产品因为尊重用户而被记住，不靠放大用户对时间流逝的恐惧获得打开率。

---

## 17. 明确不进入核心的方向

- AI 朋友或伴侣养成
- 用户可见 Multi-Agent 角色团队
- AI 代写用户人生
- 未来自我数字分身
- 逝者分身或数字永生
- 情绪评分、人格报告、趋势 dashboard
- 自动完整记录一天的 Life OS
- 公开信、社交流、匿名树洞
- 以建议质量与通用 AI 正面竞争
- 用历史记录证明用户现在「应该」怎样

任何翻案必须建立新的 Type C change，并首先论证它没有破坏本宪章的第一人称权利、当下优先、无记录焦虑与数据主权。

---

## 18. 尚未冻结、需要验证的问题

以下事项有方向性建议，但没有被 v0.1 定义为需求：

1. 时间篇章的创建、命名、片段归属与结束机制
2. 快速记录后的「这一刻已经留下」仪式形态
3. Agent 何时可以追问、何时应保持安静的体验规则
4. 隐含含义如何在不打断用户的前提下形成可撤销记忆
5. 过去记录何时可以参与当前理解，以及用户如何授权、查看和纠正
6. 环境数据线索的权限、主动性与端侧处理方式
7. 私人时间册、长期导出与跨平台托管形态
8. 可持续商业模型与长期服务承诺
9. 高风险安全响应、人工接管与未成年人策略
10. 产品视觉、声音、动效与品牌系统

这些问题 SHOULD 优先通过原型、合成场景与真实用户访谈验证，再决定是否进入 OpenSpec。

## 19. 新能力五问

任何未来功能在进入 proposal 前，必须回答：

1. 它是否帮助用户表达或保存真实的此刻？
2. 它是否增加当下价值，或以克制方式增加时间复利？
3. 最终内容与解释权是否仍然属于用户本人？
4. 记忆与环境数据的使用是否经过明确同意，并且可以撤销？
5. 去掉 AI 炫技后，这项体验是否仍然服务核心用户故事？

若不能回答，默认不进入主线。

## 20. 与当前 C1–C9 的关系

C1–C9 已形成 Loop、Tool、Memory、Guardrail、Trace、Eval、Reflection、Resilience 与 Temporal Intelligence 能力。本宪章不重新验收这些能力，也不声称全部理想体验已被实现。

它为后续方向提供新的筛选方式：

- Loop 应服务表达，而不是迫使用户完成对话阶段
- Tool 应服务用户确认过的低风险动作
- Memory 应保存具体经历，不建立不可撤销的人格结论
- Guardrail 应保护第一人称原文与时间归属
- Trace / Eval 应证明编排可靠而不泄露内容
- Reflection 应提高忠实度，不提高话术侵入性
- Resilience 应让失败不破坏托付感
- Temporal Intelligence 应把历史证据温柔交还，而不是分析用户人生

若现有行为与以上长期方向存在差距，应形成残余问题或新的 OpenSpec proposal，不得通过本文件直接修改业务代码。

## 21. v0.1 决策摘要

| 决策 | 已确认结论 |
|---|---|
| 核心价值 | 保存用户具体活过的证据 |
| 价值兑现 | 当下保存即成立；时间是复利 |
| 核心用户 | 结果未定、正在认真生活且有时刻想留下的人 |
| 产品品类 | 私人的生命片段记录空间 |
| 最小单位 | 此刻片段 |
| 长期容器 | 时间篇章；具体机制待验证 |
| AI 角色 | 有朋友温度的见证者 |
| AI 中心性 | 第二入口、主动召唤；记录可独立完成 |
| 记忆原则 | 具体经历优先，不形成稳定人格结论 |
| 当下原则 | 不为长期建模打断当前表达 |
| 时间原则 | 不要求回看、感动或回应 |
| 完整性 | 允许遗漏和空白，不制造记录焦虑 |
| 数据来源 | 只有用户主动选择的内容成为生命记录 |
| 数据权利 | 可查看、导出、删除；不以数据锁定用户 |
| 粘性 | 信任粘性与时间粘性优先于高频活跃 |
| 安全 | 紧迫人身风险是当下表达优先的窄例外 |
| 理想时刻 | 基于生命证据的温柔回望 |
