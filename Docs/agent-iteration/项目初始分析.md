## 二、诚实评价：Agent 化的差距有多大

> [!IMPORTANT]
> **当前的 AI 集成≠ Agent。** 现在是 "AI as a tool call"，不是 "AI as an agent"。这个差距不是代码量的差距，而是**架构思维的差距**。

### 什么是 Agent（对比你的 RAG 项目）

| 维度 | RAG 项目 | Flashback 现状 | Agent 应有的样子 |
|------|---------|---------------|-----------------|
| AI 交互模式 | 检索 → 增强 → 生成 | 单轮 prompt → response | **多轮对话 + 自主决策 + 工具调用** |
| 推理能力 | 依赖检索质量 | 无推理，纯模板 prompt | **Chain-of-Thought + ReAct** |
| 记忆 | 向量化文档 | 无记忆，每次重新来 | **短期对话记忆 + 长期用户画像** |
| 工具使用 | N/A | N/A | **Agent 调用多个 tool 完成任务** |
| 自主性 | 被动检索 | 被动调用 | **主动感知 + 自主执行** |
| 规划能力 | 无 | 无 | **Task decomposition + Planning** |

### 两个简历项目的互补定位

```
RAG 项目 → 证明你理解 "如何让 AI 基于企业知识回答问题"
         → 检索增强生成、向量化、chunk strategy、可信度
         
Flashback → 应该证明你理解 "如何让 AI 成为一个能自主行动的助手"
          → Agent 架构、Tool calling、Memory、Planning、Evaluation
```

> [!TIP]
> 如果 RAG 解决的是 **"AI 知道什么"**，那 Agent 解决的是 **"AI 能做什么"**。两个项目正好覆盖 AI 应用的两个核心方向。

## 三、Flashback Agent 化的独特优势

> [!NOTE]
> Flashback 的产品气质——"帮助用户写下当下，让未来的自己重新理解这一刻"——天然适合做一个**温柔的、陪伴式的写作 Agent**，而不是一个效率工具 Agent。这是面试中极好的差异化叙事。

### 为什么这个项目适合做 Agent

1. **多轮交互天然存在**：用户写记录不是一次性的，是逐步展开的（情绪 → 困惑 → 核心问题 → 期望）
2. **工具调用场景丰富**：位置、图片、语音、标签、封存、解锁——这些都是 Agent 可以调用的 tool
3. **长期记忆有意义**：用户的历史记录就是 Agent 的长期记忆，"三个月前你写过类似的焦虑" 这种能力极有价值
4. **规划和引导有意义**：Agent 可以根据用户状态，主动建议 "你已经三天没有记录了" 或 "上周的焦虑现在怎么样了"
5. **评估和反思有意义**：时间回看本身就是一种 evaluation loop

## 四、Agent 化改造方案建议

### 架构层面：引入 Agent Runtime

```
                        ┌──────────────────────────┐
                        │    Agent Orchestrator     │
                        │  (ReAct / Plan-Execute)   │
                        └────────┬─────────────────┘
                                 │
                    ┌────────────┼────────────────┐
                    │            │                │
              ┌─────▼────┐ ┌────▼─────┐ ┌────────▼────────┐
              │  Memory   │ │  Tools   │ │   Evaluation    │
              │  Module   │ │  Module  │ │   Module        │
              └──────────┘ └──────────┘ └─────────────────┘
                    │            │                │
         ┌─────────┴──┐    ┌───┴────┐      ┌────┴─────┐
         │ Short-term │    │Record  │      │ Quality  │
         │ (对话上下文)│    │Location│      │ Metrics  │
         │ Long-term  │    │Media   │      │ User     │
         │ (历史记录)  │    │Tag     │      │ Feedback │
         └────────────┘    │Seal    │      └──────────┘
                           │Search  │
                           └────────┘
```

### 具体改造点（按优先级排序）

#### P0：Agent 核心能力（简历必须体现）

| 改造点 | 现状 | 目标 | 技术关键词 |
|--------|------|------|-----------|
| **多轮写作引导** | 单轮 prompt | Agent 持有对话状态，逐步引导用户展开记录 | ReAct pattern、Conversation State Machine |
| **Tool Calling** | 无 | Agent 可调用：保存草稿、添加位置、添加标签、封存、AI 整理等 | Function Calling / Tool Use API |
| **用户记忆** | 每次重新来 | Agent 检索用户历史记录，做个性化引导 | Long-term Memory、Embedding + 向量检索 |
| **主动触发** | 被动调用 | 解锁时主动生成"时间对话"，结合历史 | Event-driven Agent Trigger |

#### P1：Agent 进阶能力（加分项）

| 改造点 | 说明 | 技术关键词 |
|--------|------|-----------|
| **情绪轨迹分析** | 基于历史记录的情绪变化曲线，Agent 自主分析 | Structured Output + Time Series |
| **写作风格适配** | Agent 记住用户的表达偏好，调整 prompt 风格 | Few-shot Learning from History |
| **智能标签推荐** | Agent 基于内容自动推荐标签 | Classification + Tool Call |
| **跨记录关联** | "这和你 X 月 Y 日写的那条记录有关" | Semantic Search + Agent Reasoning |

#### P2：工程展示能力（证明工程素养）

| 改造点 | 说明 |
|--------|------|
| **Agent 可观测性** | 记录每次 Agent 决策链路：thought → action → observation |
| **Guardrails** | Agent 不做心理诊断、不替换用户原文（符合产品初心） |
| **Evaluation 框架** | Agent 输出质量评估：相关性、温柔度、准确性 |
| **Provider 中立** | 现有的 provider 适配模式扩展到 Agent runtime |

## 六、风险和注意事项

> [!WARNING]
> **不要为了 "Agent" 而 Agent。** 以下几点必须注意：

1. **产品初心不能丢**：Flashback 的气质是"安静、私密、克制、温柔"。Agent 不是让它变成一个话痨 chatbot，而是一个**懂你的安静陪伴者**。
2. **M4 范围约束**：当前 M4 是"核心功能准生产可用"，Agent 化改造应该作为 **M5 或独立 change** 来规划，不能混入 M4。
3. **复杂度控制**：不需要实现一个通用 Agent 框架。只需要在 Flashback 的具体场景下，展示 Agent 的核心思想。
4. **不要重复 RAG**：Flashback Agent 的记忆系统可以用向量检索，但叙事重心是 Agent 架构和 Tool Calling，不是 RAG pipeline。
5. **工程边界**：AGENTS.md 明确禁止"complex AI scoring / diagnosis / dashboard"和"major backend rewrite"。Agent 化需要在这些约束内找到可行路径。

## 七、总结评价

### 可行性：⭐⭐⭐⭐ (4/5)

项目有天然的 Agent 化土壤：多轮交互、丰富工具、长期记忆、情感理解。技术栈也支持——Spring Boot 后端可以托管 Agent runtime，现有的 AI provider 适配层可以复用。

### 简历价值：⭐⭐⭐⭐⭐ (5/5)

RAG + Agent 的组合在 2026 的 AI 工程师简历上是**极强的差异化**。RAG 证明你会做知识系统，Agent 证明你会做智能助手——覆盖了 AI 应用层的两大核心方向。

### 改造难度：⭐⭐⭐ (3/5)

核心 Agent 能力（多轮引导 + Tool Calling + Memory）的 MVP 可以在现有架构上增量实现，不需要大规模重写。难点在于 Evaluation 和 Guardrails 的设计，以及如何在"克制"的产品气质下展示 Agent 能力。

### 建议路径

```
Step 1: 完成 M4（当前优先级不变）
Step 2: 提 M5 OpenSpec change → "Agent-powered Writing Companion"
Step 3: 实现 Agent 核心：多轮引导 + Tool Calling + Memory
Step 4: 补 Evaluation 和 Guardrails
Step 5: 整理 Agent 架构文档，作为简历叙事支撑
```

> [!TIP]
> **一句话总结**：Flashback 做 Agent 化不是"硬拗"，而是产品本身就在呼唤一个更智能的陪伴者。关键是把 Agent 的技术深度做出来，同时保持产品的温柔和克制。
