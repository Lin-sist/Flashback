# E1 目标用户观察主持手册

> 状态：`READY / SKIPPED`；当前没有可用参与者
> 样本目标：5–8 名有效成年人
> 证据边界：定性心智模型观察，不作统计显著性声明

## 1. 研究问题

比较同一组合成片段在三种信息模型中的表现：

- A：独立片段 + 标签/时间范围；
- B：用户定义的时间篇章；
- C：不拥有片段的轻量“这一段”时间视图。

观察用户是否自然需要一个可命名、可结束、可重开的生活容器，以及它是否比标签/时间筛选产生真实任务增益而不制造分类压力。

## 2. 有效参与者

- 优先招募正处于结果未定阶段、偶尔保存生活片段的成年人；
- 已参与 E1 讨论、设计、原型实现或内部走查的人不得计入有效样本；
- 只使用 `P01`～`P08`，不记录身份、账号、联系方式、公司或唯一设备标识；
- 参与者须知原型不会保存任何内容，并同意记录非隐私的结构化观察；
- 主持人解释正确模型后，该轮记 `invalid`；关键交互故障记 `blocked`。

## 3. 启动方式

在仓库根目录运行：

```powershell
python -m http.server 4312 --bind 127.0.0.1 --directory Docs/design
```

打开：

```text
http://127.0.0.1:4312/e1-time-chapter/prototype.html?variant=A
```

页面必须持续显示“E1 研究原型 · 合成材料 · 不会真实保存”。默认不录音、不录屏、不截图。

## 4. 开场白

> 这是一个不会真实保存任何内容的研究原型。我们观察的是界面表达，不是在测试你。请只使用页面里的合成片段；过程中可以随时停止。除非页面无法继续，我不会告诉你应该怎样整理这些记录。

不要提前解释“篇章”的正确含义，不要说 B 是目标方案，也不要提示新片段应该归入某组。

## 5. 六人顺序平衡

| 参与者 | 变体顺序 |
|---|---|
| P01 | A → B → C |
| P02 | B → C → A |
| P03 | C → A → B |
| P04 | A → C → B |
| P05 | C → B → A |
| P06 | B → A → C |

P07/P08 优先补偿无效或阻断场次；若前六场均有效，选择两个不同顺序并在结论中注明不完全平衡。

## 6. 合成任务

每个变体重置后依次完成：

1. 找到与“最近这段准备搬家的生活”相关的片段；
2. 处理一条新的合成片段，允许选择不归入任何组；
3. 表示这段生活暂时告一段落；
4. 模拟后来事情又继续，尝试继续补充；
5. 删除分组或视图，并说明原片段是否仍存在。

不要使用参与者的真实阶段、真实日记、照片、声音或地点。

## 7. 单轮提问

- “这里的记录为什么会被放在一起？”
- “如果不用页面上的词，你会怎样称呼这一组？”
- “新记录一定要放进某一组吗？”
- “结束意味着什么？之后还能继续吗？”
- “删除这一组后，原记录还在吗？”
- “它和标签、文件夹、时间筛选或目标进度有什么不同？”
- “哪一步让你觉得是在整理任务，而不是留下生活？”

三轮结束后再问哪一种方式真正帮助找回并继续一段生活，以及原因。偏好票数不能单独决定结论。

## 8. 中止与隐私

参与者准备输入私人内容、上传私人文件、拒绝继续，或主持人必须代为完成关键动作时，立即停止当前轮。只记录控件、状态理解、停顿线索和非隐私短摘要，不复制敏感原话。

## 9. 结论门槛

- 至少 5 名有效参与者完成全部关键任务前，结论保持 `NOT_READY`；
- 产品负责人、Agent、团队内部走查均不计为参与者；
- 当前参与者为 0，本手册只代表材料就绪，研究执行为 `SKIPPED`。
