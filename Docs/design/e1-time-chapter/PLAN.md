## 2. 这轮只回答一个问题

> 用户是否自然地把一段尚未结束、结果未知的生活理解为可命名、可结束又可重新打开的“篇章”，并且这种容器比标签和时间范围更有价值？

E1 不回答数据库表、API、DTO、迁移、页面路由、导出格式、SEALED 关联规则或生产视觉实现。上述事项只有在 E1 得到正证据后，才可能进入独立 P5.x Type C 规划。

## 3. 已核对的产品与代码事实

- 最小完整单位仍是独立的此刻片段；文字、图片或原始声音任一种都可以使记录成立；
- 用户当前可通过“我的记录”和“时光轴”浏览记录，并使用标签和时间筛选；
- 记录可以保持 SAVED、进入 SEALED、抵达为 UNLOCKED，技术 DRAFT 不进入普通列表；
- 保存不要求标题、标签、地点、Agent、未来时间或其他整理动作；
- 单条记录可以删除，基础记录可导出；容器不得削弱这些数据权利；
- 当前代码中没有 `TimeChapter`、`chapterId` 或等价持久化模型；E1 原型不能假装已有真实保存能力。

## 4. 研究结构

```text
独立片段（当前基线）
        │
        ├── A：标签 + 时间范围已经够用？
        │
        ├── B：用户命名的“时间篇章”是否形成新价值？
        │
        └── C：轻量“这一段”时间视图是否比容器更自然？

             正证据 ──▶ 才允许提出 P5.x
             压力/无增益/证据不足 ──▶ 停止，保留独立片段
```

比较对象必须在信息模型上不同，不能只是换名称、颜色或卡片样式。

### A｜独立片段 + 标签/时间范围对照

- 不引入新容器；
- 用户通过已有标签和时间范围找到一组相关片段；
- 用于判断现有能力是否已经解决任务，避免因为蓝图写了“篇章”就预设必须实现。

### B｜用户定义的时间篇章

- 用户主动创建并命名一个尚未结束的篇章；
- 片段默认不属于任何篇章，用户可在保存后或详情页主动加入；
- 第一版原型中每个片段最多一个主篇章；
- 用户可以结束、重新打开和删除篇章；删除篇章明确不删除片段；
- 不显示进度、完成度、成功/失败评价，不由 AI 自动命名或归入。

### C｜轻量“这一段”时间视图

- 用户选择一个时间范围，可选填写自己的称呼；
- 它是可保存的浏览视图，不拥有片段，也不要求逐条归类；
- 用于判断用户真正需要的是“主观生活容器”，还是更轻的时间范围与回看入口。

## 5. 原型形态

用户已授权 E1-02～E1-04；现已制作一个 throwaway、离线、单文件交互原型：

- 位置：`Docs/design/e1-time-chapter/prototype.html`；
- 通过 `?variant=A|B|C` 切换三个信息模型；
- 使用同一组合成记录卡、合成日期和合成媒体占位；
- 零登录、零 backend、零网络、零 localStorage、零 provider、零真实持久化；
- 页面常驻标识“E1 研究原型 · 合成材料 · 不会真实保存”；
- 不接入 `pages.json`、真实小程序路由或 Preview，不直接晋升为生产实现。

原型仅用于信息模型研究，不进入真实路由，也不构成 P5.x 实现授权。

## 6. 合成任务

准备一组跨 6 周的 8 条合成片段，包含两个可能相关但不完全重合的生活主题，并保留至少两条明显可独立存在的片段。每名参与者完成：

1. 找到“最近这段准备搬家生活”相关的片段；
2. 把一条新片段放到他认为合适的位置，允许选择“不归入任何一组”；
3. 表示这段生活暂时结束，并说明之后如何重新找到；
4. 模拟后来发现事情又继续，尝试重新打开或继续补充；
5. 删除分组/视图，并说明他认为原片段会发生什么。

任务提示不提前使用“篇章比标签更好”“应该归类”或“正确答案”等引导语。

## 7. 访谈问题

每个变体完成后只问与心智模型直接相关的问题：

- “这里的这些记录为什么会被放在一起？”
- “如果不用页面上的名字，你会怎么称呼这一组？”
- “新记录一定要放进某一组吗？”
- “结束之后意味着什么？还能继续吗？”
- “删除这一组后，你觉得原记录还在吗？”
- “它和标签、文件夹、时间筛选、目标进度有什么不同？”
- “刚才哪一步让你觉得是在整理任务，而不是留下生活？”

三轮结束后再问哪一种方式真正帮助理解或回看，以及哪一种造成额外压力。偏好票数不能单独构成 P5.x 证据。

## 8. 参与者与隐私边界

- 目标为 5–8 名有效参与者，优先包含正处于结果未定阶段、偶尔保存生活片段的成年人；
- 已参与 E1 设计或内部走查的人不能计入有效样本；
- 仅使用 `P01`～`P08`，不记录姓名、账号、联系方式、公司或可识别身份；
- 全程只使用合成记录，不要求参与者讲述真实人生阶段、日记、地点、照片或声音；
- 默认不录音、不录屏、不截图，只记录结构化操作结果与非隐私短摘要；
- 主持人泄露正确模型、参与者输入私人材料或原型故障阻断关键任务时，该轮记为 `invalid` 或 `blocked`，不能进入结论。

## 9. 观察字段

| 观察项 | 记录方式 |
|---|---|
| 自然命名 | 参与者未经提示使用阶段/时期/篇章/项目/标签等哪类语言 |
| 独立片段理解 | 是否理解片段可以不归入任何组 |
| 归入压力 | 是否为“必须分类”停顿、补造意义或担心放错 |
| 结束语义 | 是否理解结束不等于成功、失败或不可再打开 |
| 删除语义 | 是否理解删除容器不删除片段 |
| 查找增益 | 相比 A，B/C 是否减少寻找与解释成本，以及原因 |
| 目标化误解 | 是否把容器理解为任务、进度、打卡或完成度管理 |
| 变体偏好 | 选择与理由；不把票数直接当产品结论 |

禁止记录参与者的真实阶段内容、情绪诊断、人格推断或任何用户日记原文。

## 10. 决策规则

E1 的输出只能是 `POSITIVE`、`NEGATIVE` 或 `INCONCLUSIVE`。

### 允许形成 `POSITIVE` 的最低条件

- 至少 5 名有效参与者完成全部关键任务；
- 多数参与者无需解释就能把 B 理解为一段用户定义、仍可变化的生活，而不是文件夹、标签或目标管理；
- B 相比 A 在“找回并继续一段生活”任务中出现重复、可解释的实际增益，而不只是文案偏好；
- “可不归入、结束可重开、删篇章不删片段”三项边界没有重复误解；
- 没有至少 2 名参与者重复出现明显分类压力、结果评价或完成度压力。

满足这些条件只允许提出 P5.x proposal，不等于批准其设计或实现。

### 形成 `NEGATIVE` 或停止的条件

- 标签/时间范围已经完成同一任务，篇章没有可观察增益；
- 至少 2 名参与者重复把篇章理解为必须分类、目标进度、成败总结或不可撤销归档；
- 用户需要系统自动推断阶段才能觉得它有用，而主动创建本身没有价值；
- 结束/重开/删除语义无法在克制界面中被稳定理解。

### 保持 `INCONCLUSIVE` 的条件

- 有效参与者少于 5；
- 主持干预、原型故障或观察记录不足；
- 只有偏好票，没有任务行为和解释证据；
- B 与 C 都有局部价值，但无法回答容器是否必要。

`NEGATIVE` 或 `INCONCLUSIVE` 均不启动 P5.x。独立片段继续作为完整产品单位。
