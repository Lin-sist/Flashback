# E0 目标用户观察主持手册

> 状态：`PAUSED / SKIPPED`；当前没有可用目标用户，手册留待未来恢复
> 研究阶段：E0-04
> 样本目标：5–8 名有效参与者
> 证据边界：定性观察，不作统计显著性声明

## 1. 研究问题

比较 A / B / C 三种保存反馈与编辑层级，观察参与者是否能在不被提示正确答案的情况下理解：

1. 内容已经保存；
2. 此刻可以立即离开；
3. 封存不是完成记录的义务；
4. Agent 不是完成记录的义务。

本研究不验证 API、持久化、媒体上传、生产动效或小程序真机兼容性。

## 2. 参与者与有效场次

- 招募 5–8 名目标用户，优先包含首次使用记录产品者与已有轻量记录习惯者；
- 已参与本原型设计、实现或内部走查的人不能计入有效样本；
- 只使用 `P01`～`P08` 编号，不记录姓名、联系方式、公司、账号或可识别身份信息；
- 参与者必须知晓这是不会真实保存的研究原型，并同意主持人记录非隐私的操作观察；
- 主持人如向参与者解释了正确路径，该轮只能记为 `invalid`，不得进入结论计数。

## 3. 开场准备

在仓库根目录运行：

```powershell
python -m http.server 4311 --bind 127.0.0.1 --directory Docs/design
```

原型地址：

```text
http://127.0.0.1:4311/e0-capture-ritual/prototype.html?variant=A
```

每场开始前：

1. 按分配表打开首个变体；
2. 点击“重置”，确认状态为“未保存”；
3. 关闭浏览器自动填充、翻译或会改写页面的扩展；
4. 默认不录屏、不截图、不录音；如需记录，只写 `OBSERVATIONS.md` 允许的结构化字段；
5. 不让参与者输入真实日记、真实地点、真实姓名或上传私人文件。

## 4. 开场白

逐字或等义说明：

> 这是一个不会真实保存任何内容的交互原型。我们观察的是界面是否容易理解，不是在测试你。请只使用页面提供的合成材料；过程中可以随时停止。除非页面无法继续，我不会告诉你应该点哪里。完成每一轮后，我会问几个关于当前状态的问题。

不要提前说“保存成功后可以离开”，也不要解释封存或 Agent 的正确角色。

## 5. 六人平衡分配

文字、图片、声音的执行顺序固定；变体顺序轮换。前 6 名参与者覆盖全部 6 种变体排列，并使每个“任务 × 变体”组合恰好出现 2 次。

| 参与者 | 文字任务 | 图片任务 | 声音任务 | 变体顺序 |
|---|---|---|---|---|
| P01 | A | B | C | A → B → C |
| P02 | B | C | A | B → C → A |
| P03 | C | A | B | C → A → B |
| P04 | A | C | B | A → C → B |
| P05 | C | B | A | C → B → A |
| P06 | B | A | C | B → A → C |

如扩展到 P07 / P08，优先复制前 6 场中发生无效、设备故障或观察记录缺失的对应顺序；若前 6 场均有效，则选两个不同的顺序，并在结论中保留样本不完全平衡这一限制。

## 6. 三类任务提示

每轮先打开分配到的变体，再读对应提示。不要补充“正确做法”。

### 文字任务

> 请用页面提供的这句话留下一条你认为已经完成的记录：“傍晚下过一阵雨，窗台边的薄荷闻起来很清。”

### 图片任务

> 请用页面提供的合成图片占位留下一条你认为已经完成的记录，不补正文。

### 声音任务

> 请用页面提供的合成声音占位留下一条你认为已经完成的记录，不设置未来时间，也不使用 Agent。

“不设置未来时间，也不使用 Agent”只用于声音任务约束，不解释它们是否为完成义务。

## 7. 单轮主持流程

1. 读任务提示，开始观察；
2. 最多保持 20 秒安静，不评价、不纠正；
3. 参与者停住时，只能问：“你现在会怎么继续？”；
4. 参与者认为完成后，依次问：
   - “现在这条内容是什么状态？”
   - “如果你现在不想再做任何事，你会怎么离开？”
   - “你觉得还必须完成什么吗？”
   - “刚才哪些内容让你停顿、犹豫或担心没完成？”
5. 记录首次动作和非隐私短摘要，不记录任务内容以外的私人表达；
6. 点击“重置”，按分配表进入下一轮。

三轮结束后再问：

> 三个版本中，哪一个最让你确定“已经完成，可以离开”？为什么？

偏好只作为解释材料，不用票数直接选胜者。

## 8. 中止与无效规则

出现以下任一情况立即停止当前轮：

- 参与者准备输入真实私人内容；
- 原型故障导致任务无法继续；
- 主持人泄露正确路径或替参与者完成关键动作；
- 参与者明确表示不愿继续。

原型故障写 `blocked`，主持干预写 `invalid`，均不得把缺失字段推断为成功或失败。

## 9. 场次收尾

- 确认 `OBSERVATIONS.md` 中该参与者三行记录完整；
- 清空浏览器页面状态，原型本身 reload 后也应回到未保存；
- 不在聊天、截图、日志或 commit message 中复制参与者私人内容；
- 达到至少 5 名有效参与者前，结论始终保持 `NOT_READY`。
