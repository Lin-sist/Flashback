## 2. 这轮只回答一个问题

在用户主动保存后，哪一种低侵入反馈与编辑层级，最能同时让用户理解：

1. 这一刻已经保存成功；
2. 现在可以立即离开；
3. 不需要封存，也不需要使用 Agent；
4. 标题、分类、人生节点、AI 整理和解锁时间都不是完成记录的前置义务。

E0 不回答状态枚举、API、迁移、媒体上传、真实持久化或生产动效实现。上述问题属于 P3.1 的 Type C 规划与实现。

## 3. 已核对的当前事实

当前记录编辑页会影响原型判断的事实包括：

- `saveDraft()` 成功后提示“草稿已保存”；
- 关闭有正文的脏页面会自动持久化草稿后返回；
- 正文为空时不能保存，也不能先添加图片或声音；
- 分类、人生节点、Agent 入口、“你当时以为 / AI 整理”和解锁时间在保存前同页可见；
- 封存要求未来解锁时间，成功后自动返回；
- 首页仍以“未来重新读懂”“寄给未来”为主要叙事。

这些是研究起点，不是 E0 可以直接改写的契约。

## 4. 原型形态

采用一个明确标注为 throwaway 的单文件离线交互原型：

- 预定位置：`Docs/design/e0-capture-ritual/prototype.html`；
- 固定手机视口，沿用当前安静、纸张、私人档案的基本气质；
- 三个结构性不同的变体放在同一文件中，通过 `?variant=A|B|C` 和底部浮动切换器切换；
- 全部使用合成文字、合成图片占位与合成声音占位；不请求真实登录，不调用 backend，不写 localStorage，不发送网络请求；
- 页面常驻标识“E0 交互原型 · 合成材料 · 不会真实保存”；
- 不修改 authenticated real path 或 Preview 产品路由，避免破坏 H0 的真实能力表面；
- 原型只用于学习，形成结论后删除或吸收结论，不直接晋升为生产实现。

## 5. 三个待比较变体

### A｜当前层级对照 + 瞬时确认

- 保留当前页面中分类、人生节点、Agent、AI 整理和解锁时间的可见顺序；
- 保存后在页面中部短暂显示“这一刻已经留下，现在可以离开”；
- 不自动跳转，不出现声音，不把封存或 Agent 作为下一步 CTA。

用途：作为对照，区分“确认反馈不足”与“编辑层级本身造成负担”。

### B｜专注记录 + 持续状态条

- 首屏只保留文字 / 图片 /声音和“留下这一刻”；
- 标题、分类、人生节点、AI 与解锁时间收进一个默认折叠的“还想补充”；
- 保存成功后，主按钮变为持续可见的“已留下”，旁边明确显示“可以离开”；
- 页面保持原位，不自动展开其他能力。

用途：验证渐进披露能否减少保存前负担，同时持续状态是否比 toast 更容易被理解。

### C｜先完成，再选择

- 保存前只呈现最小记录区与媒体入口；
- 保存后出现安静的底部层：“这一刻已经留下”；
- 明确提供“先离开”和“继续添一点”，封存与 Agent 只在继续路径内以次级入口出现；
- 用户不作选择时页面不自动跳转。

用途：验证显式退出是否最清楚，以及保存后的选项是否反而制造新的流程压力。

三个变体必须在结构、信息层级和主动作上真正不同；不能只换颜色、圆角或文案。

## 6. 合成任务与访谈脚本

建议招募 5–8 名目标用户做小规模定性观察；不把结果写成统计显著性。优先覆盖首次使用者与有轻量记录习惯者。

每名参与者依次完成三类合成任务，变体顺序轮换，避免固定顺序偏差：

1. 用提供的一句合成文字留下一条你认为已经完成的记录；
2. 用提供的图片占位留下一条记录，不补正文；
3. 用提供的声音占位留下一条记录，不设置未来时间，也不使用 Agent。

任务提示不提前告诉参与者应该点击封存、Agent 或退出。每轮保存后只问：

- “现在这条内容是什么状态？”
- “如果你现在不想再做任何事，你会怎么离开？”
- “你觉得还必须完成什么吗？”
- “刚才哪些内容让你停顿、犹豫或担心没完成？”

参与者如主动提供私人内容，主持人应请其改用合成材料；不截图、抄录或保存私人日记原文。

## 7. 观察记录

只记录结构化行为与语言反馈：

| 观察项 | 记录方式 |
|---|---|
| 是否理解已保存 | 是 / 否 + 参与者自己的解释 |
| 是否理解可立即离开 | 是 / 否 + 首次尝试的动作 |
| 是否误以为必须封存 | 是 / 否 + 触发线索 |
| 是否误以为必须使用 Agent | 是 / 否 + 触发线索 |
| 分类 / 人生节点 / AI / 解锁时间负担 | 首次犹豫点与原话短摘要，不记录私人内容 |
| 保存反馈可见性 | 未注意 / 注意但不确定 / 明确理解 |
| 变体偏好 | 选择及原因；不把偏好票数直接当结论 |

禁止记录正文、标题、地点、文件名、声音内容、真实 Agent 对话、推测的情绪或人格。

## 8. 决策规则

E0 的结论不是“票数最多的界面”，而是能否排除关键误解。

- 任一关键误解在至少 2 名参与者中重复出现：该变体失败，需修改后复测；
- 若参与者普遍能理解已保存，却仍把封存或 Agent 当作完成义务：优先调整层级，不把问题归因于确认文案；
- 若持续状态最清楚但造成界面噪声：保留状态语义，重新探索更克制的视觉形态；
- 若三个变体都不能同时满足“已保存、可离开、无强制下一步”：E0 继续迭代，不创建 P3.1 proposal；
- 只有形成一条有观察依据的推荐方向，并明确仍待 P3.1 决策的状态/API/迁移问题后，才进入 P3.1 规划闸。

## 11. 内部走查结果

- A/B/C 三种变体均可通过查询参数、浮动切换器与非编辑态方向键切换；
- 文字、图片占位、声音占位三类合成任务均可独立完成，图片与声音不会要求补正文；
- A 使用短暂居中确认，B 使用持续保存状态条，C 使用保存后离开/继续分支；三者结构和主动作不同；
- 未保存时关闭不会伪装退出，已保存后退出会再次提示“原型没有真实保存任何内容”；
- C 的 Agent 与时间入口只在用户选择“继续添一点”后出现；
- 360×800、390×844、1440×900 三种视口无横向溢出，交互目标最小高度为 44px；页面 console 无 error / warning；
- 本结果只证明原型可操作和研究材料就绪，不构成目标用户理解证据，也不授权 P3.1。
