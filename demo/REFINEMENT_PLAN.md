## 1. 目标与已确认范围

保留「信笺纸 × 微液态玻璃」方向，让文字更容易阅读、纸与玻璃的层次更清楚，并让用户实际走通一段本地演示。先完善五个核心页，不重做整套界面。

用户本轮已确认：

1. 首轮精修 `home / writing / saved / timeline / look`；其余九页只做共享样式与既有链接回归。
2. 同时接通输入、保存、回看的本地演示流程。
3. 使用同源、同一标签页的 `sessionStorage`，允许跨页与刷新恢复。

成功的使用过程：

```text
首页书写空位 → 输入测试文字 → 保存到本标签页演示
                    ↑                ↓
                继续补充 ← 保存承接页 → 时光轴 → 回看同一条演示记录
```

页面必须明确「本地演示 · 不上传，请只输入测试文字」。保存承接必须说明仅保存至当前标签页演示。正常关闭标签页结束存储会话，但浏览器会话恢复可能恢复数据；不得宣传立即或不可恢复地擦除。提供显式清除本轮演示入口。

### 4.2 技术研究：事实、方案、验收分开

| 官方资料 | 核实的事实 | 本项目采用方案 |
|---|---|---|
| [MDN backdrop-filter](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backdrop-filter) | 模糊作用于背景；父层 opacity/filter/mask 等可能限定 backdrop root | RGBA 背景承载透明度；不对玻璃的整个父层降 opacity；先检查层级再调模糊 |
| [MDN length](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length) / [env](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/env) | dvh 表达动态视口；env 提供安全区 | `100vh` 回退＋支持时 `100dvh`；底部动作占独立布局行并留安全区 |
| [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport) | 软键盘可能缩小可视视口而不改变布局视口 | 先 CSS 与正常滚动；真实键盘遮挡仍存在才评估小范围事件补偿 |
| [W3C 中文排版需求](https://www.w3.org/TR/clreq/) | 版心、行长、行距需一并确定，中文标点有排版要求 | 字阶与宽度一起比较；长文不手工插 br，不滥用字距或两端对齐 |
| [W3C 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 普通文字 AA 基准 4.5:1，符合条件的大字 3:1 | 所有必读小字按 4.5:1 检查；装饰纹理单独处理 |
| [W3C target size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) / [reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html) | 目标尺寸最低规则为 24px 且含例外；重排有 320px 条件 | 本项目选择关键控制 44px 点击区；补 320px 与 200% 放大，不把此项目值冒充标准要求 |
| [web.dev 动画指南](https://web.dev/articles/animations-guide) | transform/opacity 通常比触发布局/绘制的动画更合适；will-change 应谨慎 | 不动画模糊半径，不持续动画阴影，不全局 translateZ/will-change；有性能记录再优化 |
| [MDN reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion) / [reduced transparency](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-transparency) | 相关媒体查询表达用户偏好，浏览器支持需另核实 | reduced-motion 静态等价；降低透明度作为增强项，不能替代基础实色降级 |
| [MDN sessionStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/sessionStorage) | 按源与标签页区分；刷新可保留；file/policy 可能抛 SecurityError；会话恢复有保留可能 | 同源页面、try/catch、版本化存储、错误保留输入；不宣称关闭即安全擦除 |
| [MDN Document.fonts](https://developer.mozilla.org/en-US/docs/Web/API/Document/fonts) | fonts.ready 在已使用字体加载与布局完成后兑现 | 截图记录字体加载/回退状态，不能凭截图或 check=true 单独断言实际使用字体 |

所有技术资料核实的是 Web 行为，不直接证明 Uniapp、微信 WebView 或 Skyline 可用。本轮不改小程序，也不沿用旧文档中的平台支持断言为当前验证。

## 7. 布局与材质的实施步骤

### 7.1 先建立可回归基线

1. 记录 HEAD、git status、允许文件哈希、字体模式；保留用户既有改动，禁止 reset/clean。
2. 稳定截图以页面实际内容为准：390×844 五核心页首屏与长页尾屏，三张局部材质特写，九页回归首屏。
3. 等字体与布局稳定；记录是否网络字体/系统宋体、是否减动画，不截空白或切换帧。
4. 本轮浏览器客户端连接失败，替代浏览器对 file:// 明确策略拒绝，且禁止替代地址绕过。**不得启动服务、换工具或搬运文件绕过该拒绝**。后续须在访问方式被明确允许的独立验证环境中进行，或由用户提供实际截图供人工比较；截图只能证明对应环境。
5. 基线截图无法取得时，可完成静态文件和合成逻辑验证，但视觉定稿不能写 PASS，停止批量推广候选样式。

### 7.2 纸面与玻璃先局部后共享

1. 先用现有首页＋书写页比较文字层级；只改候选语义色与正文，拍同一状态对照。
2. 保留纸底/卡面/凹陷面的明度顺序，检查纹理是否叠在文字上方、是否遮挡事件。
3. 卡片维持相同方向的接触影与柔影；去掉重复材质层时，核对所有 `.letter-card` 使用处。
4. 玻璃先改药丸一处；检查背景确有可辨结构，再决定是否需要透明度变化，不能靠加噪点增强玻璃。
5. 高光伪元素 `pointer-events:none`，继承圆角；文字在高光层上方，勿占掉现有折角伪元素。
6. 逐个检查 pill/tabbar/chip/chat-input/霜层的实色 fallback；霜层降级不能显露下方正文。
7. 参数选定后更新共享 CSS；九页回归失败先缩小选择器，不用 !important 全局压制。

### 7.3 页面壳层

桌面仍以 390×844 展示框呈现；小屏按设备视口布局。只对核心页渐进增加「状态栏/内容/动作」三行壳层，内容行 `min-height:0`、正常文档流与必要的单一纵向滚动；不要一次重写九页旧 absolute 布局。

- 小屏先 `100vh`，支持时增强 `100dvh`；保留可滚动内容，不用缩放整页塞进画布。
- 顶部仿状态栏与内容预留明确空间；回看内容不穿过状态栏。
- 动作栏在布局中占高度；若仍悬浮，内容底部预留动作高度＋安全区，末行可完整滚到栏上方。
- 书写 textarea 自动增长设合理上限后页面滚动；原生输入使用 border/background reset 与可见焦点，不用 contenteditable 模拟富文本。
- 正文默认左对齐与自然换行；长 URL/英文测试处理 overflow-wrap；不新增用于对齐的空格/br。
- 阻断输入区旁侧注与折角抢占正文；视口变窄允许留白适当减小，保留层级。
- 软键盘用真实移动设备核查；如需 VisualViewport，监听只影响书写动作区、节流并清理，不把每次视口变化认定为键盘出现。

## 8. 本地演示契约与实现步骤

### 8.1 运行与存储

- 五页保持独立 HTML 和现有路径；同源、同标签页相对链接跳转。
- 不用 target=_blank 打开演示核心路径；带 opener 的新标签页可能获得初始存储副本，不能把「按标签页区分」写成绝无复制。新开标签页不作为共享草稿方案。
- 使用原生普通脚本＋一个 demo 命名空间，不加框架、npm 依赖或打包。store 先加载，flow 后加载，脚本 defer。
- 单个版本化 key：`flashback.demo.v1.session`。不得使用 `sessionStorage.clear()`，只操作自有 key。
- 数据结构为**demo 自有模型，不是后端 DTO**：`schemaVersion`、`draft`、`savedRecord`、`lastSaveReceipt`。首轮只保存一条最新演示记录；再次保存更新同一条，不冒充记录管理系统。
- draft 包含 title/body；savedRecord 另含稳定演示 id、createdAt/updatedAt；receipt 只用于决定是否展示本次落印。展示时间来自本地操作，历史固定样本继续用样本时间。
- 初始示例来自 brief 合成内容；填写框明确为测试文字。fixture 与动态演示记录分开，动态正文不得覆盖 fixture。
- 没有 JSON 导出，没有 localStorage/IndexedDB/cookie，没有用户原文日志；URL 只带演示标识如 `demo=latest`，不带文本。
- 图片/声音/位置仍是已标注样本，不与新文字自动关联，不生成虚假附件元数据。

### 8.2 最小状态流

| 动作/状态 | 行为 | 失败与边界 |
|---|---|---|
| 从首页进入 | 链接进入 writing；有演示 draft 则恢复 | 新标签页无共享承诺 |
| 输入 | 原生 input/textarea；中文输入法组合中不重排/改写输入 | 不 trim 正文显示，不吞换行 |
| 草稿恢复 | 防抖更新 draft；保存前同步 flush | 草稿存储失败显示提示，输入仍保留 |
| 保存 | 正文非全空才允许；写 store 成功、读回匹配后再跳 saved | SecurityError/容量/JSON/版本错误各给简短说明；失败不跳转、不落印 |
| 重复点击 | 同步锁一次写入；禁用期间保持标签 | 不制造第二条记录 |
| 保存承接 | `demo=latest` 读取 savedRecord，明确本地演示成功 | 无记录则空态＋返回书写，不能用静态成功样本顶替 |
| 继续补充 | saved 内容作为 draft；同 id 更新 | 不改变 createdAt；updatedAt 可变 |
| 时光轴 | 只追加最新演示条目，独立标注演示 | 删除后移除演示项；历史封存 fixture 不受影响 |
| 动态回看 | 读取演示记录并用 textContent 输出 title/body；保持换行 | 不用 innerHTML；恶意 HTML 显示成文字；无记录不回退为假成功 |
| 删除演示记录 | 明确只删除演示项，二次确认后移除自有数据 | 不触发 ownership 的清理全部，不操作真实数据 |
| 清除本轮演示 | index 中明确入口，确认后 removeItem 自有 key | 禁止清全源存储；提示其他已开页面需刷新 |

建议 demo 输入容量：title 80 个 Unicode 码点、body 4000 个码点；均为待规划批准的演示上限，不推导正式业务限制。长文先保留完整输入并提示超限，不自动截断。边界校验只处理容量、空白与结构，禁止改写内容。

sessionStorage 读写均捕获异常；校验 schemaVersion、对象类型与字段长度。损坏存储不自动覆盖为成功，也不默默删掉，给「清除演示后重试」入口。file:// 与被禁用存储的环境不承诺跨页闭环；显示不可用说明并保持当前输入，不回退到长期存储。

页面后退/前进及 BFCache 恢复用 pageshow 重新读状态，避免已删除记录继续出现。落印只消费新保存 receipt，刷新/后退不反复制造新成功；动画结束不是保存判据。

### 8.3 页面绑定顺序

1. 给核心页 data-page 和有限 data-role；所有查询限定当前页。
2. store 先实现纯结构校验与有结果的 read/write/remove；可注入 Storage 接口进行合成验证。
3. writing 接通输入和保存；异常保留原生表单内容，按钮/错误提示有名称与关联。
4. saved 动态渲染并设置 aria-live 的短状态，焦点进入确认标题；保留继续补充与回看入口。
5. timeline 插入带演示标注的条目；look 通过显式 demo 标识选择动态渲染，否则保留固定样本。
6. home 入口恢复可点击；index 放演示说明与清除入口；不改图鉴为产品首页。
7. JS 禁用时保留静态样板阅读；动态保存入口显示需要脚本，不能误报已保存。

### 8.4 交互未纳入项

媒体按钮、语音播放、位置、Agent 对话、回应输入、真实封存/解锁、导出、清理所有权数据均不接通。核心页上的未接通控件用清楚的展示标注/disabled 状态，不在按下时弹出模拟成功。其余九页仍是静态原型，导航页统一说明。

「封」印保留既有视觉规范，但动态演示的状态明确为本地已保存，不能推导 SEALED；不连接封存页、解锁日期或修改真实封存语义。

## 9. 五页精修与九页回归

| 页 | 本批精修内容 | 必须看到的证据 |
|---|---|---|
| home | 品牌/问候/书写空位/两卡/导航层次；入口可点击 | 390 首屏主动作清楚；小屏能到导航；Tab 名不变 |
| writing | 原生输入仍像信笺；正文字阶、自然照片样本、动作栏 | 短文/长文、中文输入法、键盘、焦点、保存失败状态 |
| saved | 保存记录一致、文字层次、一次落印、明确演示成功 | 内容/时间一致；重复点击/刷新不造新记录；删除仅本地 |
| timeline | 内容形态分化、导航上方可完整读到末项、动态演示条目 | 日期/节点/条目对应；长内容可滚；固定封存项语义不变 |
| look | 主信/片段/回信层级保持；位置提示加深；动态正文可读 | 完整首尾截图；样本与动态分开；输入不变成 HTML |

九页回归重点：

- sealed：无滤镜也不能显露正文；不能仅凭 CSS 隐藏当作真实权限隔离。
- records/chapter：加深元数据后不挤压标题；筛选/动作区无横向溢出。
- user-center/ownership：守印与托管重心不变，不新增数据看板。
- summary：正文与底部动作可读，不把本地示例标为 AI 已完成真实整理。
- agent-choose/agent-writing/agent-review：浮层尺寸、背景快照与当前核心页的视觉关系；背景样板固定，不能冒充当前输入的真实 AI 对话。默认只回归不实现。

### 11.2 画面与可用性（需实际渲染）

- 主验收：390×844 五核心页首屏与长页末屏、index、九页回归。
- 压力：375×667、360×800、320px 窄视口、200% 字体/浏览器放大；这些尺寸是测试场景，不声称覆盖所有设备。
- 对照使用同一内容、同一视口、同一字体状态、相同滚动位置；先验静态终态，再看动作。
- 必读小字实际最不利背景对比度 ≥4.5:1；关键控件 44px 点击区；focus-visible 不被纹理/遮罩覆盖。
- 字体：网络成功与阻断 Google Fonts 两组，保持系统宋体回退可读；不声称离线与在线像素完全一致。
- 玻璃：正常与强制暖纸实色两组；实色组不影响按钮/导航/霜封状态理解。
- 动效：普通与 reduced-motion；所有入口、成功/失败信息在没有动画时仍成立。
- 键盘：真实移动浏览器有环境才执行；桌面缩小窗口不算软键盘验收。
- 长文：1200 字合成正文、超长标题、中英混排、换行、较长日期/状态；不要新增真实日记测试文件。
- 图像：现有两图加载失败与不同宽度；不因拉伸/裁剪丢失关键信息，保留自然色。

### 11.3 性能与证据边界

- 记录同环境滚动、按压、落印；无持续滤镜/循环动效，不把桌面流畅推为低端机 60fps。
- 只有 trace/实际设备支持时才报告帧率、耗时与峰值；不发明统一性能数字。
- 绘制昂贵的阴影/clip-path 若造成可复现卡顿，缩短/静态降级，先保操作；不引入新依赖。
- 微信开发者工具、小程序真机、正式 API/provider/对象存储：本轮均不执行，分别记 SKIPPED/out_of_scope；HTML 浏览器通过不替代这些证据。
